# Phase 4.5 — API docs (api.sap.com) implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use [`superpowers:subagent-driven-development`](../../../C:/Users/I809764/.claude/plugins/cache/claude-plugins-official/superpowers/5.0.5/skills/subagent-driven-development) (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship api.sap.com API documentation as the sixth content type in the knowledge graph, surfaced on concept landing pages + tutorial-OP sidebars as authoritative `officialReferenceFor` references.

**Architecture:** Three tasks landing as commit ranges on a single shared branch and a SINGLE PR (squash-merged; matches Phase 4.1-4.4 actual shipping pattern):

1. **Chassis + corpus fetcher + seed (Task 1)** — `ApiDocs` + `ApiDocConceptLinks` + `JobLastRun` entities, NEW `srv/lib/api-sap-com-fetcher.js` (with api.sap.com discovery probe + YAML-only fallback fork), `OtherResource` CDS type extended, GC iteration extended, IRI prefix wired, `SHORT_BY_TYPE` updated, TTL chassis edit (3650 → 1095), hand-curated `db/data/api-docs.yaml` (50-80 entries), `scripts/seed-api-docs.cjs`, YAML schema validator, hybrid schema sanity test.
2. **Cron + extraction + admin action (Task 2)** — `api-doc-extract.js` adapter (single predicate `officialReferenceFor`, floor 0.7, cap 6), `fetch-api-docs-job.js` monthly cron with MAX-or-abort first-run gate, `AdminService.KnowledgeGraphSettings.seedApiDocs()` action (XSUAA `@requires: 'Admin'`), projection helper, neighborhood enrichment widens to 5-array variadic merge (helper unchanged from 4.3), counter rename `teachesWritten` → `linksWritten`, admin UI tile for `JobLastRun` last-run-age display, hybrid end-to-end test.
3. **UI (Task 3)** — concept-page section #6, sidebar `OtherResource` `'api-doc'` widening (5th branch), `/build/concepts` payload extension, Hugo frontmatter pipe, telemetry events `kg.api-doc.linked_from_concept_page` + `kg.api-doc.linked_from_sidebar`.

**Tech Stack:** SAP CAP (Node.js 20), HANA Cloud, vitest (unit + hybrid), Hugo, Vue 3 islands. Native `fetch` against api.sap.com discovery endpoint (probe + fallback). gpt-4o-mini for extraction; text-embedding-3-small for merge-on-write.

## Controller gates before subagent dispatch

Two steps in this plan are NOT subagent-executable and must be done by the controlling agent (or Tom) BEFORE dispatching implementer subagents:

1. **Task 1 §1.1 — api.sap.com discovery probe (Steps 1-3).** The probe is a literal `curl` call from a shell with network access; its outcome forks Task 1's implementation between §1.2-A (HTTP mode) and §1.2-B (YAML-only). A subagent cannot meaningfully execute this step because the outcome shapes its own subsequent work. **Controller runs the probe, commits the probe-results doc, and only THEN dispatches the Task 1 implementer with the resolved fork.**

2. **Task 1 §1.5 — YAML seed curation (Steps 17a-17c).** The 50-80 entries are operator-curated SAP knowledge requiring `sap-devs` MCP research + Tom's review. A subagent would fabricate slugs and URLs. **Controller drafts the candidate list using `mcp__sap-devs-server__search_resources`, presents to Tom, finalises after approval, THEN includes the curated `db/data/api-docs.yaml` in the Task 1 dispatch context.**

Both gates are one-time per phase; subsequent sub-phases of the chassis (4.6/4.7) don't need them.

- **Schema changes MUST run `npx cds build --production`** — external-namespace artefacts go to gitignored `gen/db/src/gen/`; no tracked artefacts stage. Phase 4.1-4.4 commits show the same pattern. But `JobLastRun` lives in `db/schema.cds` (NOT external namespace) — that one DOES stage tracked artefacts. Re-stage `db/last-dev/csn.json` and `db/src/JobLastRun-*.hdbtable` accordingly.
- **No pre-commit hook in this repo** — no `.husky/`. Run `npx vitest run` before committing.
- **Native fetch only.**
- **No raw SQL** — except the established HANA LOB escape hatch (Phase 4.5 follows the LOB-locator mitigation; never SELECT `description` alongside metadata via CDS QL).
- **Slug case canonicalisation** — ApiDoc slugs are `ad-<lowercased_sourceId>` (case-stable). `Concepts.slug` are case-sensitive; keep lowercase.
- **One link table** — `ApiDocConceptLinks` only. No service-junction sibling (unlike Phase 4.3/4.4).
- **`lastExtractedHash` UPDATE is the FINAL step per package** — #708 chassis pattern.
- **MAX-or-abort first-run gate** — cron refuses to self-bootstrap on empty `ApiDocs`; operator must run `scripts/seed-api-docs.cjs --commit` first (OR `POST /admin/seedApiDocs`).
- **Counter rename** — Phase 4.5 cron uses `linksWritten` (not `teachesWritten`) because the predicate is `officialReferenceFor`, not `teaches`.
- **api.sap.com probe outcome forks Task 1 Step 1** — both probe-success and probe-fail (YAML-only) are documented shipping paths. Task 1 plan ships both implementation forks.
