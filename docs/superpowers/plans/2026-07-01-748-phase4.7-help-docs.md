# Phase 4.7 — Help docs (help.sap.com + cap.cloud.sap + ui5.sap.com) implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use [`superpowers:subagent-driven-development`](../../../C:/Users/I809764/.claude/plugins/cache/claude-plugins-official/superpowers/5.0.5/skills/subagent-driven-development) (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship narrative documentation from three sources (help.sap.com + cap.cloud.sap + ui5.sap.com) as the eighth content type in the knowledge graph, surfaced on concept landing pages at position **#3** and tutorial-OP sidebars as `explains` references — semantically distinct from `officialReferenceFor` (Phase 4.5's api.sap.com signatures).

**Architecture:** Three tasks landing as commit ranges on a single shared branch and a SINGLE PR (squash-merged; matches Phase 4.1-4.6 pattern):

1. **Chassis + three fetchers + orchestrator (Task 1)** — `HelpDocs` + `HelpDocConceptLinks` entities (one entity with `source` discriminator), three fetcher modules under `srv/lib/help-docs/` (help-sap-com, cap-cloud-sap, ui5-sap-com) + `index.js` orchestrator with `contentHash` dedupe + source precedence, `OtherResource` CDS type extended with `source`/`sourceLabel`/`anchor`/`snippet`/`product`, GC iteration extended, TTL entry, IRI prefix + `SHORT_BY_TYPE`, lockstep test 13 → 14, hybrid schema sanity test, cross-source dedupe unit test.
2. **LLM extraction + cron + admin action (Task 2)** — `help-doc-extract.js` adapter (single predicate `explains`, cap 8, K=25 registry hint, optional anchor), `fetch-help-docs-job.js` weekly cron on `'17 5 * * 3'`, `scripts/seed-help-docs.cjs` operator CLI, registration via #756 `registerJob` chassis, projection helper, neighborhood widens to 7-array variadic merge (helper unchanged), `AdminService.seedHelpDocs()` admin action, `snippet` denorm at link INSERT, hybrid end-to-end test, hybrid cascade-delete audit extension.
3. **UI (Task 3)** — concept-page section INSERT at position **#3** (with the ripple: existing sections #3-#8 shift down one slot), source badge CSS (three tint variants), sidebar `OtherResource` `'help-doc'` widening (7th branch), `/build/concepts` payload extension with `helpDocs[]`, Hugo frontmatter pipe, telemetry events (`kg.help-doc.linked_from_concept_page` + `kg.help-doc.linked_from_sidebar` + `kg.help-doc.seed_triggered`).

**Tech Stack:** SAP CAP (Node.js 22), HANA Cloud, vitest (unit + hybrid + smoke), Hugo, Vue 3 islands. Native `fetch` for all three sources; existing `TUTORIALS_GITHUB_TOKEN` (with `GITHUB_TOKEN` env-var fallback per `scripts/parsers/github.ts:205`) covers cap-cloud-sap fetcher. gpt-4o-mini for extraction; text-embedding-3-small for merge-on-write.

- **Schema changes MUST run `npx cds build --production`** — external-namespace artefacts land in gitignored `gen/db/src/gen/`; no tracked artefacts stage. Phase 4.1-4.6 commits show the same pattern. **NO new schema in `db/schema.cds` (main namespace)** — Phase 4.7 only adds to `db/external-content.cds`.
- **No pre-commit hook in this repo** — no `.husky/`. Run `npx vitest run` before committing.
- **Native fetch only.**
- **No raw SQL** — except the established HANA LOB escape hatch.
- **Slug case canonicalisation** — HelpDoc slugs are `hd-<source>__<canonicalPath>` (lowercase, slug-safe; length ceiling 150). `Concepts.slug` are case-sensitive; keep lowercase.
- **One link table** — `HelpDocConceptLinks` only. No service-junction sibling (unlike Phase 4.3/4.4).
- **`lastExtractedHash` UPDATE is the FINAL step per row** — #708 chassis pattern.
- **MAX-or-abort first-run gate** — cron refuses to self-bootstrap on empty `HelpDocs`; operator must run `scripts/seed-help-docs.cjs --commit` OR click admin "Seed help docs" button first.
- **Counter naming** — Phase 4.7 cron uses `linksWritten` (matches Phase 4.5/4.6 convention). Extraction summary log includes `hasAnchorCount` + `nullAnchorCount` for anchor-invention spot-checking (§4.3 of spec).
- **`registerJob` chassis (#756) is the cron registration path** — NOT `cron.schedule` directly. The new cron auto-appears on the admin Cron health tile.
