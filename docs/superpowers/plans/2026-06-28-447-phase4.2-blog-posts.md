# Phase 4.2 Blog Posts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship SAP Community blog posts as the second new graph node type under the Phase 4 chassis. Daily cron pulls posts from Khoros search API, extracts `discusses` concept links via LLM, and surfaces posts on Phase 3 concept landing pages + the tutorial-OP sidebar.

**Architecture:** Three stacked PRs sharing one branch:

1. **Chassis (PR-1)** — `BlogPosts` + `BlogPostConceptLinks` entities, `khoros-blogs-client.js` MCP-shaped wrapper, GC iteration extended, IRI prefix wired, `SHORT_BY_TYPE` updated.
2. **Cron + backfill (PR-2)** — `blog-post-extract.js` adapter, `fetch-blog-posts-job.js` daily cron, `scripts/seed-blog-posts.cjs` one-shot 24mo backfill, projection helper, neighborhood enrichment populates `otherResources` blog-post rows.
3. **UI (PR-3)** — concept-page "Blog posts discussing this" section, sidebar `OtherResource` `'blog-post'` widening, `/build/concepts` payload extension, Hugo frontmatter pipe-through.

**Tech Stack:** SAP CAP (Node.js 20), HANA Cloud, vitest (unit + hybrid), Hugo, Vue 3 islands. Khoros search API (anonymous tier) for the corpus; gpt-4o-mini for extraction; text-embedding-3-small for merge-on-write.

## Cross-cutting reminders for every task

- **Schema changes MUST run `npx cds build --production`** and stage the generated `db/last-dev/csn.json` + `db/src/*.hdbmigrationtable` files in the same commit. Per `feedback_cds_build_production_not_cds_compile_for_last_dev`.
- **Slug case canonicalisation** — Blog post slugs are `bp-<numeric>` and have no case ambiguity. Other read/write paths (`Concepts.slug`, `Tutorials.slug`) ARE case-sensitive; keep lowercase per project convention.
- **Native fetch only** — `khoros-blogs-client.js` uses Node 20+ native `fetch`, not Axios. Set timeout via `AbortController`.
- **No raw SQL** — use `cds.ql` everywhere except the existing `loadConceptRegistry` HANA escape hatch (which is already factored into `srv/lib/kg-merge-on-write.js`).
- **No pre-commit hook in this repo** — no `.husky/` directory exists; CI enforces formatting/staging guards instead. Run `npx vitest run` before committing if you want local validation.
