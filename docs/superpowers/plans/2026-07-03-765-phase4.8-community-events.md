# Phase 4.8 — SAP community events implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use [`superpowers:subagent-driven-development`](https://github.com/anthropics/claude-plugins-official/tree/main/superpowers/skills/subagent-driven-development) (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship SAP community events (CodeJams, Devtoberfest, TechEd, user groups) as the ninth content type in the knowledge graph, surfaced on concept landing pages at position **#10** and tutorial-OP sidebars as `covers` references — first live consumer of the reserved `endDate + 30d` date-aware TTL branch.

**Architecture:** Three tasks landing as commit ranges on a single shared branch and a SINGLE PR (squash-merged; matches Phase 4.1–4.7 pattern):

1. **Chassis + two fetchers + orchestrator (Task 1)** — `CommunityEvents` + `CommunityEventConceptLinks` entities (one entity with `eventType`/`source` discriminators), two fetcher modules under `srv/lib/events/` (khoros-fetcher, rss-fetcher) + `index.js` orchestrator with `sourceId` dedupe + past-event filter, `OtherResource` CDS type extended, GC `ITERATION_SET` extended with a real date-aware branch (not the reserved-skip that shipped in Phase 4.3), TTL registry entry, IRI prefix + `SHORT_BY_TYPE`, lockstep test 14 → 15, hybrid schema sanity test, dedup + past-filter unit tests.
2. **LLM extraction + cron + admin action (Task 2)** — `community-event-extract.js` adapter (single predicate `covers`, cap 6, K=15 registry hint, no anchor), `fetch-community-events-job.js` twice-weekly cron on `'31 4 * * 1,4'`, `scripts/seed-community-events.cjs` operator CLI, registration via #756 `registerJob` chassis, projection helper `buildCommunityEventTriples`, neighborhood widens to 8-array variadic merge (helper unchanged), `AdminService.seedCommunityEvents()` admin action, `snippet` denorm at link INSERT, hybrid end-to-end test, hybrid cascade-delete audit extension.
3. **UI (Task 3)** — concept-page section INSERT at position **#10** (append after Samples #9, before Prerequisites), sidebar `OtherResource` `'community-event'` widening (data-driven; zero Vue code changes), `RESOURCE_TYPE_CONFIG` entry at priority 80, `/build/concepts` payload extension with `communityEvents[]`, Hugo frontmatter pipe, telemetry event `kg.community-event.linked_from_concept_page`, docs updates.

**Tech Stack:** SAP CAP (Node.js 22), HANA Cloud, vitest (unit + hybrid + smoke), Hugo, Vue 3 islands. **Native `fetch` only** (no MCP transport, no third-party HTTP client). Vendored JS ports of the Khoros REST client and RSS reader from `D:\projects\sap-devs-cli\internal\events\`. `gpt-4o-mini` for extraction; `text-embedding-3-small` for merge-on-write.

## Global Constraints

- **Never call the `sap-devs-server` MCP `search_events`.** Fetchers are direct HTTP to Khoros and RSS endpoints, mirroring the vendored `sap-devs-learning.js` / `sap-devs-discovery.js` precedent. This is a hard user directive from the brainstorm session.
- **Entity name is `CommunityEvents`** — cannot reuse `Events` (name is taken by `db/schema.cds:227` mission-attendance entity, referenced by `Missions`, `PrizeRecords`, `TaskRecords`).
- **Predicate is `covers`** — single, not multi. No sibling `services` link table.
- **No capacity / seats / registration-status modelling.** Upstream payload does not carry this data.
- **No geographic personalization in 4.8.** `location`, `scope`, `virtualOrInPerson` are stored but extraction ignores them. `Users.region` is deferred to Phase 4.9+.
- **Native `fetch` only.** No `axios`, `node-fetch`, `got`. (Global rule from user CLAUDE.md.)
- **No raw SQL.** Use `cds.ql` / CQL. The one HANA LOB escape hatch (SELECT column via raw SQL to avoid locator lifetime issues) already exists elsewhere and does not apply here.
- **`lastExtractedHash` UPDATE is the FINAL step per row** — #708 crash-safety chassis pattern, no deviation.
- **`registerJob` chassis (#756) is the cron registration path** — NOT `cron.schedule` directly.
- **`auditEvent` first arg is the action name** (`'kg.community-events.seed'`, NOT `'SecurityEvent'`). Post-#769 canonical.
- **Icon is emoji, not `sap-icon://…`** — spec §5 said `sap-icon://calendar` but every existing `RESOURCE_TYPE_CONFIG` entry uses an emoji (🎓📝🔍▶️📖🧪📚). Use `📅` for consistency. **This overrides spec §5.**
- **Cron minute `:31` is free** in `scheduler.js`'s used-minutes set (`:00 :03 :05 :07 :11 :13 :15 :17 :23 :30 :33 :43 :45 :47`). Schedule `31 4 * * 1,4` (Mon+Thu 04:31 UTC) is locked.
- **Cache dir** — the fetcher writes to `.cache/events/`. `.gitignore` line 105 (`.cache/`) already covers it; no gitignore edit needed.
