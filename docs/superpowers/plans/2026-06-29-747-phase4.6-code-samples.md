# Phase 4.6 — Code samples (SAP-samples GitHub org) implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use [`superpowers:subagent-driven-development`](../../../C:/Users/I809764/.claude/plugins/cache/claude-plugins-official/superpowers/5.0.5/skills/subagent-driven-development) (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship SAP-samples GitHub repositories as the seventh content type in the knowledge graph, surfaced on concept landing pages + tutorial-OP sidebars as `embodies` references — semantically distinct from `teaches` pedagogy.

**Architecture:** Three tasks landing as commit ranges on a single shared branch and a SINGLE PR (squash-merged; matches Phase 4.1-4.5 actual shipping pattern):

1. **Chassis + corpus fetcher (Task 1)** — `Samples` + `SampleConceptLinks` entities, NEW `srv/lib/sap-samples-fetcher.js` (direct GitHub REST API with 3-rule auto-filter), `OtherResource` CDS type extended, GC iteration extended, IRI prefix ADDED (verified not pre-staked), `SHORT_BY_TYPE` updated, lockstep test 12 → 13, hybrid schema sanity test.
2. **Cron + extraction + admin action (Task 2)** — `sample-extract.js` adapter, `fetch-samples-job.js` weekly cron, `scripts/seed-samples.cjs` operator CLI, registration via #756 `registerJob` chassis, projection helper, neighborhood enrichment widens to 6-array variadic merge (helper unchanged from 4.3), `AdminService.seedSamples()` admin action, **`runJobByName` chassis extension** to thread `opts` through to cron fn (preserves logId for the 4 logId crons), hybrid end-to-end test.
3. **UI (Task 3)** — concept-page section #7 (with `↗` link-out + language badge), sidebar `OtherResource` `'sample'` widening (6th branch), `/build/concepts` payload extension, Hugo frontmatter pipe, new `formatRelativeMonth` helper, telemetry events `kg.sample.linked_from_concept_page` + `kg.sample.linked_from_sidebar`.

**Tech Stack:** SAP CAP (Node.js 22), HANA Cloud, vitest (unit + hybrid), Hugo, Vue 3 islands. Direct GitHub REST API (no MCP) with `TUTORIALS_GITHUB_TOKEN` from credstore (env-var fallback `GITHUB_TOKEN` for hybrid dev). gpt-4o-mini for extraction; text-embedding-3-small for merge-on-write.

## Cross-cutting reminders for every task

- **Schema changes MUST run `npx cds build --production`** — external-namespace artefacts land in gitignored `gen/db/src/gen/`; no tracked artefacts stage. Phase 4.1-4.5 commits show the same pattern. **NO new schema in `db/schema.cds` (main namespace)** — Phase 4.6 only adds to `db/external-content.cds`.
- **No pre-commit hook in this repo** — no `.husky/`. Run `npx vitest run` before committing.
- **Native fetch only.**
- **No raw SQL** — except the established HANA LOB escape hatch.
- **Slug case canonicalisation** — Sample slugs are `sa-<org>__<repo>` (lowercase, slug-safe). `Concepts.slug` are case-sensitive; keep lowercase.
- **One link table** — `SampleConceptLinks` only. No service-junction sibling (unlike Phase 4.3/4.4).
- **`lastExtractedHash` UPDATE is the FINAL step per repo** — #708 chassis pattern.
- **MAX-or-abort first-run gate** — cron refuses to self-bootstrap on empty `Samples`; operator must run `scripts/seed-samples.cjs --commit` OR click admin "Seed samples" button first.
- **Counter rename** — Phase 4.6 cron uses `linksWritten` (not `teachesWritten`) because the predicate is `embodies`. Matches Phase 4.5 precedent.
- **`registerJob` chassis (#756) is the cron registration path** — NOT `cron.schedule` directly. The new cron auto-appears on the admin Cron health tile.
- **`runJobByName` opts extension is the riskiest change** — must preserve `(logId)` for the 4 logId crons (`ngds-retry`, `account-merge-batch`, `runReconciliationJob`, `runContributorNotificationsCycle`). Backward-compat test in `test/unit/srv/run-job-by-name-opts.test.js` is mandatory.
- **`TUTORIALS_GITHUB_TOKEN` is the canonical credstore key** (env-var fallback to `GITHUB_TOKEN` for hybrid dev parity with `scripts/parsers/github.ts:205`).
- **`auditEvent` first arg is the action name** (`'kg.samples.seed'`, NOT `'SecurityEvent'`). Phase 4.5's seedApiDocs was fixed by #769; Phase 4.6 starts correct.
- **Two grep verifications before Task 1's IRI add:**
  1. `grep -A 15 "KG_IRI_PREFIXES" srv/lib/kg-projection.js` should end at `'api-doc'` (drift catch).
  2. `grep -c "cron.schedule\|registerJob" srv/jobs/scheduler.js` should return 25 after the cron is registered (was 24 after #756).
