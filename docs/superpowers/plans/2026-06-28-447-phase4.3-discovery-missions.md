# Phase 4.3 Discovery Missions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship SAP Discovery Center missions as the third new graph node type under the Phase 4 chassis. Weekly cron pulls missions from the `sap-devs` MCP `search_discovery` tool, extracts `teaches` concept links + free-form `usesServices` BTP-service tags via LLM, and surfaces missions on Phase 3 concept landing pages + the tutorial-OP sidebar with effort + category labels.

**Architecture:** Three stacked PRs sharing one branch:

1. **Chassis + MCP client (PR-1)** — `DiscoveryMissions` + `DiscoveryMissionConceptLinks` + `DiscoveryMissionServices` entities, implement `sap-devs-client.searchDiscovery` (scaffolded as throw in Phase 4.1), GC iteration extended, IRI prefix wired, `SHORT_BY_TYPE` updated, shared `categoryLabel` lookup module, `OtherResource` CDS type extended with `effortLevel` + `categoryLabel`.
2. **Cron + extraction (PR-2)** — `discovery-mission-extract.js` adapter, `fetch-discovery-missions-job.js` weekly cron, projection helper, neighborhood enrichment populates `otherResources` mission rows.
3. **UI (PR-3)** — concept-page section #4, sidebar `OtherResource` `'discovery-mission'` widening, `/build/concepts` payload extension, Hugo frontmatter pipe-through with `categoryLabel` resolution.

**Tech Stack:** SAP CAP (Node.js 20), HANA Cloud, vitest (unit + hybrid), Hugo, Vue 3 islands. SAP Developers MCP (`sap-devs-server`) `search_discovery` tool for the corpus; gpt-4o-mini for extraction; text-embedding-3-small for merge-on-write.

## Cross-cutting reminders for every task

- **Schema changes MUST run `npx cds build --production`** and stage the generated `db/last-dev/csn.json` + `db/src/*.hdbmigrationtable` files in the same commit. Per `feedback_cds_build_production_not_cds_compile_for_last_dev`.
- **No pre-commit hook in this repo** — no `.husky/` directory exists; CI enforces formatting/staging guards. Run `npx vitest run` before committing if you want local validation.
- **Native fetch only** — Node 20+ built-in.
- **No raw SQL** — use `cds.ql` everywhere except the established HANA LOB escape hatch in `kg-merge-on-write.js`.
- **Slug case canonicalisation** — Mission slugs are `dm-<numeric>` (case-stable). Other slugs (`Concepts.slug`, etc.) ARE case-sensitive; keep lowercase per project convention.
- **Two link tables** — Phase 4.3 is the first sub-phase with two link tables per mission (`DiscoveryMissionConceptLinks` + `DiscoveryMissionServices`). DELETE-then-INSERT pattern applies to both. Dedup-by-conceptId for concepts; dedup-by-`serviceName.toLowerCase()` for services.
- **`lastExtractedHash` UPDATE is the FINAL step per mission** — Phase 4.1's #708 chassis pattern. Any failure before that UPDATE leaves the mission re-queueable next cycle.
- **`categoryLabel` resolution** — short codes (`onboard`, `intgn`) come from MCP; English labels (`Onboarding`, `Integration`) come from the shared `srv/lib/discovery-mission-categories.js` helper. Backend stays slug-only except where the sidebar pre-resolves it (neighborhood enrichment).
