## 1. Summary

Phase 4.5 ships api.sap.com API documentation as the **sixth content type** in the knowledge graph, alongside tutorials, learning journeys, blog posts, discovery missions, and videos. Each api.sap.com package becomes a graph node connected to concepts via a new `officialReferenceFor` predicate, expressing authoritative reference semantics distinct from `teaches`.

The architecture lifts the Phase 4 chassis verbatim — schema shape, merge-on-write (#707), crash-safety gate (#708), variadic neighborhood merge (helper unchanged), shared IRI registry, GC iteration, telemetry conventions — with three structural deltas from prior sub-phases:

1. **YAML-seeded corpus + LLM-extended monthly cron** — `db/data/api-docs.yaml` is the day-1 source of truth for which api.sap.com packages exist; the monthly cron extends the catalog via direct api.sap.com discovery AND extracts concept links via LLM.
2. **Direct api.sap.com fetcher** — new sibling to `youtube-corpus-fetcher.js` (not MCP-wrapped). An explicit probe of api.sap.com's discovery surface happens early in the plan, with YAML-only graceful degradation if all probe candidates fail.
3. **Single predicate `officialReferenceFor`** — vs Phase 4.3/4.4's two-predicate adapters. Simpler extraction; one link table (no service-junction sibling).

50-80 hand-curated entries seed the corpus on day 1; the monthly cron extends + re-extracts. Concept landing pages get section #6 "Official reference documentation" between Videos and Prerequisites. The tutorial-OP sidebar's "Other resources" widens to a 5-array merge.

### Out of scope

- Per-endpoint / per-resource graph nodes. Phase 4.5 graph nodes are **whole API packages only** (per design decision Q1). Endpoint-level granularity is a future-phase concern.
- Hand-curated concept ↔ api-doc link assertions. The YAML governs which API docs exist; the cron LLM owns linking (per Q3).
- Embedded iframe / modal rendering of api.sap.com pages. External links open in a new tab via `target="_blank"` (per Q12). CSP / X-Frame-Options concerns are deferred.
- A separate `searchResources` MCP integration. Phase 4.5 fetches api.sap.com directly. `sap-devs-client.js`'s `searchResources()` TODO-throw remains a TODO for Phase 4.6/4.7.
- Backfill of api-doc data into Phase 4.1-4.4 entities (none needed — pure additive change).
- Multi-language api.sap.com content (English only).
- Cross-org API references (e.g. third-party SAP API documentation). Matches Phase 4 architecture spec's "out of scope (probably ever)" list.

## 3. Architectural decisions (Q1-Q12)

Twelve decisions resolved during brainstorming, with rationale:

| # | Decision | Rationale |
|---|---|---|
| Q1 | **Whole API package** as graph node (not per resource/endpoint) | api.sap.com lists ~hundreds of packages, each a coherent reference unit (e.g. "CAP CQN Reference"). Per-endpoint granularity would yield 1000s of nodes with little aggregate signal and prohibitive curation cost. Whole-package matches concept-page UX (~3-6 references per concept). |
| Q2 | **YAML-seeded corpus + LLM-extended monthly cron** | YAML guarantees day-1 catalog quality with operator-vetted coverage; cron expands as new APIs land on api.sap.com. Hybrid mitigates "empty cron catalog" risk of pure cron-driven discovery. |
| Q3 | **LLM-only linking** (cron extracts concept links; YAML does not assert them) | Keeps the chassis identical to Phase 4.1-4.4 (cron is link source-of-truth). YAML governs ONLY which API docs exist; LLM decides which concepts each references. Simplifies dual-ownership concerns. |
| Q4 | **Predicate `officialReferenceFor`** (single, distinct from `teaches`) | Captures the authority semantic ("this API doc is THE reference for X concept") in a single predicate. Cleaner than two-predicate extraction (4.3 + 4.4 idiom). Distinct predicate enables future authority-weighted ranking on concept pages. |
| Q5 | **Standard chassis with link entity** (not direct column on Concepts) | Preserves chassis uniformity, allows multiple api-docs per concept with confidence scoring, matches the GC / projection / sidebar paths that all sibling phases use. |
| Q6 | **50-80 hand-curated seed packages** | High initial UX value without prohibitive curation cost. Covers the dominant concept categories (auth, integration, data, UI, ABAP, CAP, SDK). Seed shape researched + drafted during plan-writing. |
| Q7 | **Monthly cron** at `'23 4 1 * *'` (1st of month, 04:23 UTC) | api.sap.com catalog drift is slow (1-3 new packages/month at most). Weekly or twice-weekly is wasted LLM spend. Monthly cycle matches content velocity. |
| Q8 | **540-day TTL** (aggressive) | Catches catalog drift faster than the 3650-day pre-staked value. Trades sensitivity to cron outage (>18 months silent failure → catalog empty) for fresher catalog state. Mitigated by cron-health monitoring (decision §3 scope). |
| Q9 | **Section #6 — last before Prerequisites** | Additive ordering matches Phase 4.1-4.4 pattern. Final page order: Tutorials → Learning Journeys → Blog Posts → Discovery Missions → Videos → **API docs** → Prerequisites. Authority position (above-the-fold) is a future v2 concern. |
| Q10 | **Sidebar: title + `· Official reference` meta** | Single-line text. No thumbnail (api-docs don't have them; matches Q12). Distinguishes visually from blog/video/etc. rows on the same sidebar list. |
| Q11 | **Direct api.sap.com fetch** (not MCP-wrapped `searchResources`) | api.sap.com is public + stable + first-party. Custom fetcher gives finer control over pagination, retry, schema validation. Probe of discovery endpoint happens in Plan Task 1 Step 1; YAML-only fallback if probe fails. |
| Q12 | **Plain external link + ↗ icon** | Matches Phase 4 chassis pattern (target="_blank" + rel="noopener"). Link-out icon (↗) signals external authority at a glance. No iframe/modal. |

## 4. Architecture

### 4.1 Data model

Two new entities under namespace `com.sap.developers.ims.external` in `db/external-content.cds`:

```cds
// Phase 4.5 (#746): api.sap.com API documentation packages
entity ApiDocs : cuid, managed {
  slug              : String(80) @assert.unique;
  title             : String(255);
  description       : LargeString;       // NCLOB — see §10 LOB-locator note
  url               : String(500);       // canonical api.sap.com URL
  sourceId          : String(120);       // upstream identifier from api.sap.com
  contentHash       : String(64);        // SHA-256(title+description+category+apiType)
  lastExtractedHash : String(64);        // #708 crash-safety gate
  firstSeenAt       : Timestamp @cds.on.insert: $now;
  lastSeenAt        : Timestamp;
  pinUntil          : Timestamp;         // chassis admin override

  // API-doc-specific:
  category          : String(80);        // e.g. 'CAP', 'S/4HANA', 'BTP'
  apiType           : String(40);        // e.g. 'odata-v4', 'rest', 'soap', 'reference'

  links             : Composition of many ApiDocConceptLinks on links.apiDoc = $self;
}

entity ApiDocConceptLinks : cuid, managed {
  apiDoc       : Association to ApiDocs @assert.notNull;
  concept      : Association to ims.Concepts @assert.notNull;
  predicate    : String(40);             // 'officialReferenceFor'
  confidence   : Decimal(3, 2);          // 0.00-1.00; LLM floor 0.7
  extractedAt  : Timestamp;
  modelVersion : String(40);
}

annotate ApiDocConceptLinks with
  @assert.unique.apiDocConcept : [apiDoc, concept, predicate];
```

**Slug format:** `ad-<canonicalizedSourceId>` (e.g. `ad-cap_cqn_reference`). Lowercase + slug-safe transformation in the seed loader + cron upsert path. Stored canonically; case-sensitive equality checks use `LOWER(slug)` (matches sibling phases).

**`description` is `LargeString` (NCLOB)** — same Phase 4.4 lesson learned: CDS caps non-LOB strings at 5000 chars. api.sap.com descriptions can exceed that. Mitigation: HANA LOB-locator-expiry rule — never SELECT description alongside metadata via CDS QL. The cron pulls only `ID/contentHash/lastExtractedHash` from existing rows during upsert; projection / payload / neighborhood reads omit description entirely. Listing UI surfaces show title + category + apiType only.

### 4.2 YAML seed shape

`db/data/api-docs.yaml`:

```yaml
# Phase 4.5 (#746): hand-curated api.sap.com starter corpus.
# 50-80 entries on day 1; cron extends from here.
# Edit + open PR + merge + redeploy + run seed-api-docs.cjs --commit (or admin UI button).

- sourceId: CAP_CQN_Reference
  title: SAP Cloud Application Programming Model — CQN Reference
  url: https://api.sap.com/package/CAP_CQN_Reference
  description: |
    Reference documentation for SAP CAP's Core Query Notation (CQN)...
  category: CAP
  apiType: reference

- sourceId: API_BUSINESS_PARTNER
  title: SAP S/4HANA Cloud Business Partner API
  url: https://api.sap.com/api/API_BUSINESS_PARTNER
  description: |
    OData v2 service for managing business partners...
  category: S/4HANA
  apiType: odata-v2
```

**YAML schema** (validated by `npm run validate-api-docs-yaml` — schema-only, no DB hit; runs in CI on every PR touching `db/data/api-docs.yaml`):

| Field | Type | Constraint |
|---|---|---|
| `sourceId` | string | required, unique within file, `^[A-Za-z0-9_\-]+$` |
| `title` | string | required, length 5-255 |
| `url` | string | required, starts with `https://api.sap.com/` |
| `description` | string | required, length ≥ 20 |
| `category` | string | required, length 2-80 |
| `apiType` | string | required, one of: `odata-v2`, `odata-v4`, `rest`, `soap`, `reference`, `graphql`, `other` |

**Seed loader contract** (`scripts/seed-api-docs.cjs`):

- Reads `db/data/api-docs.yaml`.
- Validates schema (rejects entire run on any validation error).
- Computes `contentHash` per entry.
- UPSERTs `ApiDocs` (insert-if-missing, update-if-hash-changed on the chassis-owned fields).
- DOES NOT write `ApiDocConceptLinks` (cron's job; per Q3).
- Idempotent across reruns. Re-running after no YAML changes results in zero writes.
- CLI flags: `--commit`, `--dry-run` (default), `--slug <slug>` (single-package update for hot-fixes).
- Concurrent invocations are prevented by sharing the cron's `runWithLock('fetch-api-docs', ...)` lock — the seed script throws if the cron is mid-run, and the cron skips a cycle if the seed script holds the lock.

### 4.3 Corpus fetcher

`srv/lib/api-sap-com-fetcher.js` — sibling to `youtube-corpus-fetcher.js`. Module-singleton state via `globalThis Symbol`. Test seam: `_setMockFetcher` + `_resetForTests`.

**Discovery probe** (executed in Plan Task 1 Step 1 BEFORE writing the fetcher):

| Priority | Candidate | Expected shape |
|---|---|---|
| 1 | `https://api.sap.com/odata/1.0/catalog.svc/Packages?$format=json` | OData v2 catalogue |
| 2 | `https://api.sap.com/api/sitemap.xml` | sitemap fallback |
| 3 | `https://api.sap.com/shell/discover/external/contenthub/data/...` | frontend listings JSON |

If all three fail (auth required, rate-limited, useless shape, etc.), the fetcher falls back to **YAML-only mode**: `fetchApiSapComCorpus()` returns the entries from `db/data/api-docs.yaml`. The cron then functions as a pure re-extraction loop (LLM-extends links over the curated seed) — no corpus extension.

**Public API:**

```javascript
/**
 * Discover api.sap.com packages.
 * Returns array of normalized rows:
 *   { sourceId, title, description, url, category, apiType }
 *
 * @param {object} opts
 * @param {Set<string>} [opts.seenSourceIds] — skip these (cron's per-cycle filter)
 * @param {number} [opts.limit=5000] — total row cap (backfill safety)
 * @param {Function} [opts.yamlFallbackLoader] — test seam for YAML-only mode
 */
export async function fetchApiSapComCorpus({ seenSourceIds = null, limit = 5000, yamlFallbackLoader = null } = {}) { ... }
```

**Pagination + retry:**
- 50 rows per page (matches sibling fetchers).
- 200-page safety backstop (matches sibling fetchers).
- Native `fetch` only (Node 20+ baseline).
- Retries via Phase 4 chassis `withRetry` (exponential backoff, 3 attempts, jitter).
- Per-page timeout 30s.
- Rejects rows missing `sourceId` or `url`.
- Canonicalizes + de-duplicates `sourceId` (lowercase, slug-safe).

### 4.4 LLM extraction adapter

`srv/lib/api-doc-extract.js` — clones `srv/lib/discovery-mission-extract.js` (single-predicate sibling). Uses shared `extractConceptsCore({system, user, schema, callModel})`.

**System prompt** captures api-doc authority semantics:

> You are extracting concepts from a SAP API package's reference documentation on api.sap.com.
>
> Identify the technical concepts this API is the AUTHORITATIVE reference for.
> Aim for 1-4 concepts. Each concept comes with:
>   - slug: stable kebab-case identifier. Reuse from REGISTRY HINT when fits.
>   - name: human-readable label. REQUIRED.
>   - confidence: 0.0-1.0; floor 0.7 (api-doc authority demands high confidence).
>
> Do NOT include concepts the API merely mentions in passing. Only emit a concept when this API is the canonical reference SAP developers would look up to use that concept.
>
> You will be given a K=25 list of registry concepts. STRONGLY PREFER reusing a registry slug.

**Output schema** (single predicate):

```json
{
  "officialReferenceFor": [
    { "slug": "cap-cqn", "name": "CAP Core Query Notation", "confidence": 0.95 }
  ]
}
```

**Post-validation rules:**
- `confidence ≥ 0.7` (floor)
- `name` required (string, length ≥ 2 chars)
- Cap 6 concepts per package (extras silently dropped)
- Slugs canonicalized to lowercase kebab-case (matches `Concepts.slug` convention)

### 4.5 Monthly cron

`srv/jobs/fetch-api-docs-job.js` — clones `srv/jobs/fetch-videos-job.js`.

**Cron flow:**

1. **Budget gate** — `ChatSettings.apiDocsExtractBudgetPerCycle` (default 50) read speculatively via try/catch; absent column → default. Same idiom as 4.1-4.4.
2. **MAX-or-abort first-run gate** — `SELECT MAX(lastSeenAt) FROM ApiDocs`. If empty AND no `sinceIsoOverride` override: ABORT cycle with `summary.errors++` and log:
   > `fetch-api-docs: ApiDocs is empty; refusing to self-bootstrap. Run scripts/seed-api-docs.cjs first.`
   Same operator-safety net Phase 4.4 introduced.
3. **Fetch corpus** — `fetchApiSapComCorpus({ seenSourceIds })`. Returns ALL packages from probe-discovered endpoint, or YAML-only fallback rows.
4. **Per-package upsert** —
   - `slug = "ad-" + canonicalizeSourceId(row.sourceId)`
   - `contentHash = sha256(title + description + category + apiType)`
   - UPSERT via canonical `SELECT id WHERE LOWER(slug)=?` → INSERT-or-UPDATE pattern (matches Phase 4.4 publish-content-session.js precedent).
   - Existing row read pulls ONLY `ID`, `contentHash`, `lastExtractedHash` (LOB-locator mitigation).
5. **Per-package extract gate** — skip if `existing.contentHash === incoming.contentHash` AND `existing.lastExtractedHash === existing.contentHash`. Increment `skippedNoChange`.
6. **Extract concept links** — `extractConceptsFromApiDoc({ title, description, category, apiType, registry })`. Output: array of `{ slug, name, confidence }`.
7. **Merge-on-write** — `resolveConceptCandidates` from `srv/lib/kg-merge-on-write.js`. Returns `{ resolved, pendingMints, counters }` (#707 chassis).
8. **Link table writes** — `ApiDocConceptLinks` rows. Dedup by `(apiDoc_ID, concept_ID, predicate)`. Single link table (no service-junction).
9. **`lastExtractedHash` UPDATE as FINAL step** — #708 chassis pattern. Last write per package.

**Summary counters** (shape matches 4.4 minus `servicesWritten`):

```javascript
{
  fetched, upserted, extracted, skippedNoChange,
  mergedAtExtract, mintedAtExtract, skippedNoEmbed, teachesWritten,
  promptTokens, completionTokens, errors, budgetExhausted,
}
```

(Counter name `teachesWritten` is preserved from chassis even though the predicate is `officialReferenceFor` — sibling phases use the same generic counter for "link rows written this cycle.")

**Test injection seams:** `embed`, `extractFn`, `budgetOverride`, `sinceIsoOverride`. No `apiKeyOverride` (api.sap.com is public, no auth).

**Schedule registration** in `srv/jobs/scheduler.js`:

```javascript
// Phase 4.5 (#746): monthly api.sap.com catalog refresh + concept-link extraction
cron.schedule('23 4 1 * *', async () => {
  await runWithLock('fetch-api-docs', 30 * 60 * 1000, async () => {
    const { runFetchApiDocs } = await import('./fetch-api-docs-job.js');
    return runFetchApiDocs();
  });
});
```

### 4.6 Cron-health monitoring

Phase 4.5's 540-day TTL creates a tail risk: a >18-month cron outage silently empties the catalog from the UI. Mitigation:

- **`JobLastRun` entity** (new in this phase, or extension of existing `JobLocks` — confirmed during plan-writing): records `(jobName, lastSuccessAt, lastErrorAt, lastErrorMessage)` after each cron cycle.
- **All Phase 4 crons emit `JobLastRun` rows retroactively** — small additive change benefits all sub-phases (4.1-4.4 + 4.5).
- **Admin UI tile** surfaces last-run-age per cron name. Visual highlight when `age > 35 days` for monthly crons, `age > 14 days` for weekly, etc. No code-level alerting; operator monitors visually.
- **`POST /admin/seedApiDocs`** action gives operators a button to manually trigger the seed without `cf ssh`. Same code path as the CLI script. Bearer auth.

If the chassis already has equivalent monitoring (verified in Plan Task 1), reuse + extend. If not, this is a small addition that benefits all Phase 4 crons retroactively.

### 4.7 Projection helper

`srv/lib/kg-projection.js` — `buildApiDocTriples({apiDocs, links})`:

```javascript
export function buildApiDocTriples({ apiDocs = [], links = [] } = {}) {
  const triples = [];
  const linksByApiDocSlug = new Map();
  for (const l of links) {
    if (!l.apiDocSlug || !l.conceptSlug) continue;
    if (!linksByApiDocSlug.has(l.apiDocSlug)) linksByApiDocSlug.set(l.apiDocSlug, []);
    linksByApiDocSlug.get(l.apiDocSlug).push(l);
  }
  for (const a of apiDocs) {
    if (!isWithinTTL('api-doc', a.lastSeenAt)) continue;
    const iri = iriApiDoc(a.slug);
    triples.push([iri, 'rdf:type', 'kg:ApiDoc']);
    triples.push([iri, 'kg:title', JSON.stringify(a.title)]);
    triples.push([iri, 'kg:slug', JSON.stringify(a.slug)]);
    if (a.category) triples.push([iri, 'kg:category', JSON.stringify(a.category)]);
    if (a.apiType) triples.push([iri, 'kg:apiType', JSON.stringify(a.apiType)]);

    for (const l of linksByApiDocSlug.get(a.slug) ?? []) {
      triples.push([iri, 'kg:officialReferenceFor', iriConcept(l.conceptSlug)]);
    }
  }
  return triples;
}
```

Wired into the main projection orchestrator alongside `buildVideoTriples` (Phase 4.4) etc.

### 4.8 `/build/concepts` payload extension

`srv/lib/published-concepts-query.js` — add per-concept `apiDocs[]` (8-row cap, ordered by `category ASC, title ASC`):

```javascript
const { ApiDocs, ApiDocConceptLinks } = cds.entities('com.sap.developers.ims.external');

if (conceptIds.length === 0) {
  for (const c of concepts) c.apiDocs = [];
} else {
  const apiDocLinks = await SELECT.from(ApiDocConceptLinks)
    .columns(
      'concept_ID',
      'apiDoc.slug as apiDocSlug',
      'apiDoc.title as title',
      'apiDoc.url as url',
      'apiDoc.category as category',
      'apiDoc.apiType as apiType',
    )
    .where({ concept_ID: { in: conceptIds } })
    .orderBy('apiDoc.category asc', 'apiDoc.title asc')
    .limit(8 * conceptIds.length);

  const apiDocsByConceptId = new Map();
  for (const link of apiDocLinks) {
    if (!apiDocsByConceptId.has(link.concept_ID)) apiDocsByConceptId.set(link.concept_ID, []);
    const arr = apiDocsByConceptId.get(link.concept_ID);
    if (arr.length < 8) {
      arr.push({
        slug: link.apiDocSlug,
        title: link.title,
        url: link.url,
        category: link.category,
        apiType: link.apiType,
      });
    }
  }
  for (const concept of concepts) {
    concept.apiDocs = apiDocsByConceptId.get(concept.ID) ?? [];
  }
}
```

**Critical:** does NOT pull `description` (LOB-locator mitigation).

### 7.2 Cost ceiling estimate

| Stage | LLM cost | Quota / rate-limit |
|---|---|---|
| Seed loader | $0 (no LLM) | ~5 INSERTs/UPDATEs |
| First cron cycle (50-80 packages) | ~$0.25 one-time | 1 catalog fetch + ~5 pagination + 50-80 LLM extractions |
| Steady-state monthly | ~$0.03 | 5-10 new/updated packages (content-hash gate filters the rest) |

### 7.3 Concurrency safety

The seed script and the cron share `runWithLock('fetch-api-docs', ...)` (`srv/lib/job-lock.js`). Each one will wait or skip when the other holds the lock:

- Seed script holds lock during YAML import → cron skips its monthly cycle (recorded in `JobLastRun.lastErrorMessage`).
- Cron holds lock during monthly cycle → seed script throws with a clear message; operator retries.

Lock TTL: 30 minutes (sized for largest plausible run — seed 80 entries OR monthly 50 LLM extractions).

### 7.4 Probe failure graceful degradation

If api.sap.com discovery probe fails (Plan Task 1 Step 1) — auth required, rate-limited, useless shape — Phase 4.5 still ships:

- Fetcher falls back to YAML-only mode: `fetchApiSapComCorpus()` returns the entries from `db/data/api-docs.yaml`.
- Cron functions as pure re-extraction loop (LLM-extends links over the curated seed; no corpus extension).
- Monthly catalog growth becomes 100% manual (operator edits YAML + PR + redeploy).
- Spec acceptance criterion #4 reduces to "cron extends links only, not corpus" — still passes.

This degradation is documented in Plan Task 1 Step 1 and called out in the operator runbook.

## 10. Gotchas & operational notes

### 10.1 HANA LOB-locator on `description`

`ApiDocs.description` is `LargeString` (NCLOB). Same Phase 4.4 lesson learned: never SELECT it alongside non-LOB metadata via CDS QL. **Four read sites** in this phase MUST omit description (verified during implementation):

| Site | Mitigation |
|---|---|
| Cron upsert path (existing-row read) | Pulls only `ID/contentHash/lastExtractedHash` |
| `kg-projection.js` `loadFixtures` | Omits description |
| `published-concepts-query.js` payload | Omits description |
| `kg-neighborhood-merge.js` enrichment | Omits description |

Fresh description always comes from the api.sap.com row, never from HANA mid-cycle.

### 10.2 Slug case canonicalization

`ApiDocs.slug` is lowercase kebab-case (`ad-<canonicalized_sourceId>`). The seed loader canonicalizes `sourceId` from YAML before computing the slug:
- `CAP_CQN_Reference` → `cap_cqn_reference` → slug `ad-cap_cqn_reference`
- Both seed loader and cron use canonical `SELECT id FROM table WHERE LOWER(slug) = ?` lookup (matches sibling phases).

### 10.3 `Concepts.publishedAt`/`publishedBy` columns

Concepts may exist before any api-doc references them. The merge-on-write mint path does NOT set `publishedAt`/`publishedBy` (those are tutorial-content concerns). Same as Phase 4.2-4.4.

### 10.4 `srv-qa` cp list

If any new module under `srv/lib/` is added (it is — `api-sap-com-fetcher.js`, `api-doc-extract.js`), re-walk transitive `./` imports from `srv/lib/content-store.js` and verify every dependency is in `.deploy/mta.yaml`'s `srv-qa` `cp` list. Missing deps crash QA boot at MTA deploy time. (Same `srv-qa` audit applies to 4.1-4.4 too — chassis discipline.)

### 10.5 CAP 10 readiness

Phase 4.5 inherits the CAP 10 compatibility audit performed in 4.1. No new compat flags used; no removed flag references introduced. Runs cleanly under both CAP 8 and 10.

### 10.6 Bootstrap MAX-or-abort interaction with Helm/MTA deploy

First deploy of Phase 4.5 to a fresh subaccount lands the schema + cron registration with an empty `ApiDocs` table. The very next first-of-month would hit the MAX-or-abort gate and abort with a log line — no data loss, just a skipped cycle. The operator runbook (§7) makes seed loading the explicit first post-deploy step to avoid this.
