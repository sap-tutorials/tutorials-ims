## §1 Goal & scope

Phase 4.4 adds **SAP Developers YouTube videos** as the fourth new graph node type under the Phase 4 chassis. Each video links to the concepts it teaches via the `teaches` predicate, and surfaces the SAP BTP services it features via free-form `featuresService` tags. Videos appear on concept landing pages ("Videos teaching this") and in the tutorial-OP sidebar's `otherResources` section alongside learning journeys, blog posts, and discovery missions.

### In scope

- Twice-weekly cron ingesting videos from the `@sapdevs` YouTube channel via YouTube Data API v3
- One-shot 24-month historical backfill (`scripts/seed-videos.cjs`) for ~500 historical videos
- `Videos` + `VideoConceptLinks` + `VideoServices` entities (Composition cascade; two link tables mirroring 4.3)
- LLM-based extraction adapter (`video-extract.js`) emitting two predicates: `teaches` (concepts) + `featuresService` (BTP service names, free-form)
- Concept-page section "Videos teaching this" with thumbnail rendering inline (small 120×68 thumbnails)
- Sidebar `otherResources` widening to include `video` row type (no sidebar thumbnail — preserves visual rhythm)
- Telemetry: `kg.video.linked_from_concept_page`, `kg.video.linked_from_sidebar`
- Reuse of existing `srv/lib/youtube-fetcher.js` patterns (module-singleton state, `_resetForTests` hook, channel-ID resolution)
- Reuse of existing `resolveSecret('YOUTUBE_API_KEY')` credstore wiring (already used by homepage band)

### Out of scope (explicit non-goals)

- **Multi-channel ingestion.** Only `@sapdevs` in 4.4. Future evolution could add `@sap-tech-bytes`, `@sap-developers-de`, etc.
- **Transcript-based extraction.** YouTube auto-generated transcripts would be 10-100× larger input → ~$3-30 backfill cost vs $0.18. Description text only.
- **View count / engagement signals.** YouTube `statistics.viewCount` costs an extra quota unit per video. Not surfaced.
- **`featuresService` FK to `Products`.** Free-form strings only (matches 4.3).
- **Per-video landing pages.** Concept page + sidebar only (matches 4.1-4.3).
- **`sap-devs-client.searchVideos` MCP wiring.** Stays as throw-stub in `srv/lib/sap-devs-client.js`. Phase 4.4 departs from arch spec (which suggested the MCP path) and goes direct to YouTube Data API — same precedent as Phase 4.2's Khoros departure.

## §2 Design decisions

| ID | Decision | Rationale |
|---|---|---|
| Q1 | **Source: YouTube Data API v3 (extend existing `youtube-fetcher.js`)** | Project already has `srv/lib/youtube-fetcher.js` wired for homepage band — channel resolution, module-singleton cache, credstore-backed `YOUTUBE_API_KEY` via `resolveSecret`. Phase 4.4 adds a sibling module `youtube-corpus-fetcher.js` for full-channel pagination. Arch spec's `sap-devs.searchVideos` is a thinner wrapper that would lose direct access to description text. |
| Q2 | **Predicates: `teaches` + free-form `featuresService`** | Videos teach concepts (mirrors Tutorial's `teaches` semantic but on a separate link table) and feature SAP services explicitly in titles/descriptions (`featuresService` parallels 4.3's `usesServices`). Free-form strings, NO FK to `Products`. |
| Q3 | **TTL: 730 days (chassis-locked)** | `srv/lib/external-content-ttl.js` already declares `'video': 730` per architecture spec. Engagement-driven content — old SAP demos still teach concepts; 24-month TTL acknowledges long-tail value. |
| Q4 | **Cadence: twice-weekly Sunday + Wednesday 03:11 UTC** | SAP Developers YouTube publishes ~3-5 videos/week (Developer News weekly + Tech Bytes irregular + tutorials + conference talks). Sunday catches the week's accumulation; Wednesday catches mid-week Tech Bytes within 3 days. Off-minute `:11` separates from existing crons (`:07`, `:13`, `:23`). |
| Q5 | **Backfill: one-shot 24-month, 5000-video cap** | SAP Developers channel has ~400-500 historical videos in last 24 months. Pagination cost: ~10 YouTube quota units (10 pages × 50 videos). LLM extract cost: ~$0.18 one-time at gpt-4o-mini rates. Operator runs `scripts/seed-videos.cjs --months=24 --limit=5000 --commit` once after deploy. |
| Q6 | **LLM body cap: NONE** | YouTube descriptions run 200-5000 chars in practice. No truncation — LLM gets the full description. `description: String(8000)` provides headroom. Reasoning: description IS the primary signal (no video transcript fetch); over-truncating loses tutorial chapter information that informs concept extraction. |
| Q7 | **Budget gate: per-cycle, default 50** | `ChatSettings.videoExtractBudgetPerCycle` (default 50, twice-weekly = 100/week steady-state). 10× headroom over the ~10 new videos/cycle expected pace. Try/catch falls through to default per 4.1-4.3 idiom (column doesn't get added to schema). |
| Q8 | **Thumbnail handling: store URL, hot-link to YouTube CDN** | `Videos.thumbnailUrl: String(500)` persists YouTube's CDN URL (`https://i.ytimg.com/vi/<videoId>/hqdefault.jpg`). UI hot-links directly. CSP `img-src` must include `https://i.ytimg.com` (homepage band already proves this works). |
| Q9 | **UI: concept-page inline thumbnail + sidebar title-only** | Concept-page rows render small 120×68 thumbnails (16:9 ratio) inside the link anchor. Sidebar rows skip thumbnails to preserve the 4.1-4.3 visual rhythm (no per-row image; meta-text only). |
| Q10 | **Source departure from arch spec** | Arch spec table line for 4.4 says `sap-devs.searchVideos`. Phase 4.4 instead reuses the existing direct-YouTube-API integration (homepage already uses it with credstore key). Same precedent as 4.2's Khoros departure. `sap-devs-client.searchVideos` stays as throw-stub. |

## §3 Architecture

```text
YouTube Data API v3 (channel @sapdevs)
  ├─ /channels?forHandle=@sapdevs       ← resolves to uploads playlist ID
  ├─ /playlistItems?playlistId=<uploadsId>  ← srv/lib/youtube-corpus-fetcher.js (NEW)
  │                                          • paginated full-channel iteration
  │                                          • since-filter via publishedAt > sinceIso
  │                                          • API key via resolveSecret('YOUTUBE_API_KEY')
  │                                          • limit cap (5000 for backfill, 100 steady-state)
  │                                          • _resetForTests + _setMockFetcher hooks
  │                                          • Reuses _state.channelIdFor cache from
  │                                            existing youtube-fetcher.js
  │
  └─ HANA
      ├─ Videos entity                       (db/external-content.cds)
      ├─ VideoConceptLinks (Composition)     (predicate: 'teaches')
      └─ VideoServices (Composition)         (free-form serviceName, like 4.3)

LLM pipeline (mirrors 4.3):
  fetch listing → upsert → extract (teaches + featuresService)
                        → resolveConceptCandidates for teaches
                          (existing srv/lib/kg-merge-on-write.js)
                        → VideoConceptLinks INSERT (dedup-by-conceptId)
                        → VideoServices INSERT (dedup-by-serviceName.toLowerCase())
                        → UPDATE lastExtractedHash (#708 gate)

UI:
  hugo/layouts/concepts/single.html  — section #5 "Videos teaching this"
                                       (after Discovery Missions, before Prerequisites)
                                       — includes inline thumbnail rendering
  hugo-apps/src/related-graph/       — OtherResource.type widens to 'video';
    types.ts + RelatedGraph.vue        renders video rows with "· by ChannelName · Date"
                                       (no sidebar thumbnail)

Cron + script:
  srv/jobs/fetch-videos-job.js              — twice-weekly Sunday + Wednesday 03:11 UTC
  scripts/seed-videos.cjs                    — one-shot 24-month backfill
```

### Chassis lifts (unchanged from arch spec / 4.1-4.3)

- IRI prefix slot: `'video': 'https://developers.sap.com/kg/video/'` (already reserved at arch spec §3)
- `SHORT_BY_TYPE['video']: 'vd'` for explore-graph IRI parsing
- TTL: `external-content-ttl.js` already declares `'video': 730`
- GC cron: `srv/jobs/gc-external-content-job.js` iteration set extends to include `Videos`. Composition cascade handles both link tables. **No `pinUntil` UI** for videos in 4.4 — at 2×730 = 1460 days post-`lastSeenAt`, the GC hard-deletes the row.
- Merge-on-write: `srv/lib/kg-merge-on-write.js` (from #707) reused for `teaches` resolution
- Crash-safety gate: `lastExtractedHash` column (from #708)
- Neighborhood merge: `srv/lib/kg-neighborhood-merge.js` variadic helper (widened in 4.3) accepts a fourth array unchanged
- Telemetry chassis: same event-name + `detail` shape pattern as 4.1-4.3

### Source departure from arch spec (consistent with 4.2 precedent)

Arch spec §3.4 says "Videos: `searchVideos`" via the `sap-devs` MCP. Phase 4.4 instead extends the existing `srv/lib/youtube-fetcher.js` direct integration. Rationale:

- **Already wired:** Homepage video band uses `fetchSapDevsVideos` with credstore-resolved `YOUTUBE_API_KEY`.
- **Richer per-video fields:** Direct API exposes full description text + thumbnail URL + channelTitle + publishedAt. The MCP would wrap these but is currently scaffolded as throw-stub.
- **Quota friendliness:** 1 YouTube API call per page of 50 videos. Full backfill ≈ 10 quota units; steady-state cron ≈ 2 quota units per cycle.

`sap-devs-client.searchVideos` stays as `throw new Error('searchVideos not implemented')` in `srv/lib/sap-devs-client.js`. Future use cases (e.g. video search beyond `@sapdevs`) could wire it.

## §4 Schema (`db/external-content.cds`)

Append below Phase 4.3's `DiscoveryMissionServices` block:

```cds
/**
 * Phase 4.4 (#447): SAP Developers YouTube videos.
 *
 * - youtubeVideoId is the natural key (YouTube's 11-char video ID).
 *   slug is derived as `vd-${youtubeVideoId}` for IRI namespace-safety.
 * - description is the video's YouTube description (no body cap at fetch time).
 * - publishedAt is YouTube's snippet.publishedAt.
 * - channelTitle captured per-video for forward-compat with multi-channel ingestion.
 * - thumbnailUrl hot-links to YouTube CDN (i.ytimg.com); CSP allowance via
 *   existing homepage-band precedent.
 * - pinUntil reserved for chassis uniformity; no admin surface writes it in 4.4.
 *
 * Two link tables (matches 4.3's DiscoveryMissions pattern):
 *   - VideoConceptLinks (predicate='teaches', merge-on-write via #707)
 *   - VideoServices (free-form featuresService names, no FK)
 */
entity Videos : cuid, managed {
  slug              : String(120) @assert.unique;
  title             : String(400);
  description       : String(8000);          // up to 8K headroom; observed max ~4500
  url               : String(500);           // canonical https://www.youtube.com/watch?v=<id>
  youtubeVideoId    : String(20);            // 11-char YouTube ID
  publishedAt       : Timestamp;
  channelTitle      : String(200);
  thumbnailUrl      : String(500);

  sourceId          : String(120);           // mirrors youtubeVideoId
  contentHash       : String(64);
  lastExtractedHash : String(64);
  firstSeenAt       : Timestamp @cds.on.insert: $now;
  lastSeenAt        : Timestamp;
  pinUntil          : Timestamp;             // chassis-uniformity column; no admin surface in 4.4

  links    : Composition of many VideoConceptLinks on links.video = $self;
  services : Composition of many VideoServices    on services.video = $self;
}

entity VideoConceptLinks : cuid, managed {
  video        : Association to Videos       @assert.notNull;
  concept      : Association to ims.Concepts @assert.notNull;
  predicate    : String(20) default 'teaches';
  confidence   : Decimal(3, 2);
  extractedAt  : Timestamp;
  modelVersion : String(40);
}

/**
 * Free-form BTP service names captured per video. NOT FK to Products.
 * @assert.unique.videoService is case-sensitive on HANA; the cron's
 * case-insensitive dedup at fetch-videos-job.js (serviceName.toLowerCase())
 * is the canonical guard. Mirrors 4.3's DiscoveryMissionServices pattern.
 */
entity VideoServices : cuid, managed {
  video        : Association to Videos @assert.notNull;
  serviceName  : String(120);
  confidence   : Decimal(3, 2);
  extractedAt  : Timestamp;
  modelVersion : String(40);
}

annotate VideoConceptLinks with
  @assert.unique.videoConcept : [video, concept];

annotate VideoServices with
  @assert.unique.videoService : [video, serviceName];
```

### Build artifacts

After editing `db/external-content.cds`, run `cds build --production`. Per Phase 4.1/4.2/4.3 precedent, external-namespace artefacts land in gitignored `gen/db/src/gen/` — no tracked artefacts need staging.

### Case-sensitivity note on `@assert.unique.videoService`

CDS `@assert.unique` is case-sensitive on HANA. The cron's case-insensitive dedup at the persist step (`serviceName.toLowerCase()`) is the canonical guard. Mirrors 4.3's `DiscoveryMissionServices` pattern.

### Slug derivation

`vd-${youtubeVideoId}`. YouTube video IDs are 11 chars alphanumeric + `-_` (e.g. `dQw4w9WgXcQ`). Total slug ~14 chars. `String(120)` is generous headroom matching chassis precedent.

### Asymmetries with previous sub-phases (deliberate)

1. **Largest description column (`String(8000)`).** Reflects no-body-cap decision; observed YouTube descriptions max ~4500 chars on `@sapdevs`.
2. **`thumbnailUrl` is unique to videos.** Other content types don't render thumbnails in UI surfaces.
3. **`channelTitle` per-video, not per-channel.** Forward-compatible with multi-channel ingestion.
4. **Two link tables (matches 4.3, not 4.1/4.2).** Second sub-phase with the dual-link pattern.

### Per-video row shape (validated)

```typescript
{
  videoId: string,           // YouTube 11-char ID
  title: string,             // snippet.title
  description: string,       // snippet.description (full, no truncation; may be empty)
  publishedAt: string,       // snippet.publishedAt (ISO)
  channelTitle: string,      // snippet.channelTitle
  thumbnailUrl: string,      // snippet.thumbnails.high.url (or fallback chain)
}
```

### Pagination flow

1. Resolve channel handle → channel ID via `/channels?forHandle=@sapdevs&part=contentDetails` — pulls `contentDetails.relatedPlaylists.uploads` (the uploads playlist ID).
2. Paginate `/playlistItems?playlistId=<uploadsId>&part=snippet&maxResults=50&pageToken=<token>` until any of:
   - `nextPageToken` absent (end of channel)
   - Any item's `publishedAt < sinceIso` (caller did delta-mode, stop early)
   - `totalReturned >= limit` (caller's hard cap)
   - 200-page safety backstop
3. For each item, build canonical URL: `https://www.youtube.com/watch?v=${videoId}`.

### Validator

Throws on missing/wrong-typed fields with explicit field name:

```javascript
function validateVideoRow(row) {
  for (const field of ['videoId', 'title', 'description', 'publishedAt', 'channelTitle']) {
    if (typeof row?.[field] !== 'string') {
      throw new Error(`youtube-corpus-fetcher: row missing ${field} — ${JSON.stringify(row).slice(0, 200)}`);
    }
  }
  // thumbnailUrl is recoverable (YouTube may omit on private/deleted videos); allow empty.
}
```

`description` may be empty string (some Tech Bytes have no description) — validator checks type only.

### Caching

- **In-process channel-ID cache** (forever). Reuse the `_state.channelIdFor` map from `youtube-fetcher.js`'s module-singleton symbol if module boundaries allow shared state; otherwise create a sibling singleton. Reset via `_resetForTests`.
- **No on-disk corpus cache.** Full-channel pagination is operator-grade; unlike 4.2's `searchBlogPosts({cache: false})` opt-out, the corpus fetcher has no caching layer beyond channel-ID resolution.

### API key resolution

Resolved at cron entry point via `resolveSecret('YOUTUBE_API_KEY', { logTag: 'fetch-videos' })`. Same credstore wiring used by homepage video band. If missing → cron aborts cycle with `summary.errors++` and operator-facing log.

## §6 Extraction adapter (`srv/lib/video-extract.js`)

Mirrors `discovery-mission-extract.js` (also two-predicate). Differences:

- **System prompt:** "You are extracting concepts from an SAP Developers YouTube video. Videos teach hands-on skills via tutorials, news shows, conference talks, and demos. Identify (a) the technical concepts the video TEACHES, and (b) the SAP BTP services the video FEATURES."
- **LLM schema:** `{ teaches: [{slug, name, confidence}], featuresService: [{name, confidence}] }`. Predicate name `featuresService` differs from 4.3's `usesServices`.
- **Post-LLM rules:**
  - `teaches`: confidence floor 0.6, cap 8, name required
  - `featuresService`: confidence floor 0.7, cap 5, name minLength 2

## §7 Cron orchestration (`srv/jobs/fetch-videos-job.js`)

Schedule: `'11 3 * * 0,3'` (Sunday + Wednesday 03:11 UTC). Registered in `srv/jobs/scheduler.js` after the existing Phase 4.1/4.2/4.3 crons. Off-minute `:11` separates from existing weekly crons (`:07` discovery, `:13` journey, `:23` blog daily).

### Per-cycle flow

```text
1. Read ChatSettings.videoExtractBudgetPerCycle (default 50).
   If <= 0, exit clean. Test seam: deps.budgetOverride.
2. Load merge config (mergeSimThresholdExtract, embeddingModel).
3. Load concept registry once: loadConceptRegistry(db).
4. Resolve API key via resolveSecret('YOUTUBE_API_KEY', ...).
   If missing → ABORT with summary.errors++ + operator log.
5. Determine sinceIso. deps.sinceIsoOverride wins (backfill script
   bypasses the MAX-or-abort gate); otherwise:
     sinceIso = SELECT MAX(publishedAt) FROM Videos
     If empty: ABORT cycle (operator must run scripts/seed-videos.cjs first).
6. Fetch via fetchSapDevsVideoCorpus({apiKey, sinceIso, pageSize: 50, limit: 100}).
7. For each video:
   a. Derive slug = `vd-${videoId}`.
   b. contentHash = sha256(title + description + publishedAt + channelTitle).
   c. Upsert Videos row (NOT budget-gated). url synthesised from videoId.
   d. needsExtraction = !existing || existing.lastExtractedHash !== contentHash.
8. For each in extractQueue (bounded by budget):
   - extractFn({video, nearestConcepts}) → {teaches, featuresService, tokenUsage}
   - resolveConceptCandidates({candidates: teaches, registry, embed, ...})
   - In sequence (no explicit tx, autocommit per INSERT):
     a. INSERT pendingMints into Concepts (FK targets first; matches 4.2/4.3 shape).
     b. Warm registry with new mints.
     c. DELETE existing VideoConceptLinks for this video.
     d. Dedup resolved by conceptId (highest confidence wins).
     e. INSERT new VideoConceptLinks.
     f. DELETE existing VideoServices for this video.
     g. Dedup featuresService by serviceName.toLowerCase() (case-insensitive).
     h. INSERT new VideoServices rows (NO merge-on-write).
     i. UPDATE Videos.lastExtractedHash = contentHash
        (#708 crash-safety; FINAL step).
9. Log summary.
```

### Summary shape

```javascript
{
  fetched: 0,             // videos seen from YouTube API
  upserted: 0,            // rows touched in Videos
  extracted: 0,           // LLM calls made
  skippedNoChange: 0,
  // #707 counters:
  mergedAtExtract: 0,
  mintedAtExtract: 0,
  skippedNoEmbed: 0,
  teachesWritten: 0,
  servicesWritten: 0,
  promptTokens: 0,
  completionTokens: 0,
  errors: 0,
  budgetExhausted: false,
}
```

### Failure modes

| Failure | Cron behavior |
|---|---|
| `YOUTUBE_API_KEY` missing from credstore | Abort cycle. `summary.errors++`. Log "credstore missing YOUTUBE_API_KEY". |
| YouTube quota exhausted (HTTP 403 with `quotaExceeded`) | Abort cycle cleanly. Log "youtube quota exceeded; retry next cycle". |
| YouTube 5xx mid-pagination | Same — abort + log + retry next cycle. Already-fetched videos stay persisted; sinceIso advances next cycle. |
| Validator throws on a bad row | Skip row, `summary.errors++`, continue. |
| LLM extract throws mid-queue | Skip video; `summary.errors++`; continue. |
| Budget exhausted mid-queue | Break + `budgetExhausted: true`. Deferred videos' `lastExtractedHash` stays at prior value; re-extract next cycle. |
| Partial failure between concept INSERT and lastExtractedHash UPDATE | `lastExtractedHash` not yet updated → next cycle re-fires step 8 → DELETE-then-INSERT replaces partial state. #708 pattern. |
| Videos table empty AND no sinceIsoOverride | Abort with `summary.errors++` + operator log: "Videos is empty; refusing to self-bootstrap. Run scripts/seed-videos.cjs first." |

## §8 Backfill script (`scripts/seed-videos.cjs`)

CLI flags (mirrors 4.2's `seed-blog-posts.cjs` exactly):

```bash
node scripts/seed-videos.cjs --months=24 --limit=5000 --dry-run
node scripts/seed-videos.cjs --months=24 --limit=5000 --commit
node scripts/seed-videos.cjs --resume --commit
```

**Behavior:**

- Bypasses both `ChatSettings.videoExtractBudgetPerCycle` AND the MAX-or-abort first-run gate via two deps overrides (`budgetOverride: LIMIT`, `sinceIsoOverride: backfillSinceIso`).
- Logs per-50-video progress to stdout.
- Writes summary to `.migration-data/videos-backfill-<ts>.json`.
- Aborts cleanly on SIGINT; resumable via `--resume` (reads `MAX(publishedAt) FROM Videos` and continues forward).
- Pipeline-log entry distinguishes via `initiator` field (e.g. `manual/videos-backfill`).
- Expected volume: ~400-500 historical videos in 24mo window. ~10 quota units for pagination + 500 LLM calls.

### Backend payload (`srv/lib/published-concepts-query.js`)

```javascript
const { Videos, VideoConceptLinks } = cds.entities('com.sap.developers.ims.external');

if (conceptIds.length === 0) {
  for (const c of concepts) c.videos = [];
} else {
  const videoLinks = await SELECT.from(VideoConceptLinks)
    .columns(
      'concept_ID',
      'video.slug as videoSlug',
      'video.title as title',
      'video.url as url',
      'video.thumbnailUrl as thumbnailUrl',
      'video.channelTitle as channelTitle',
      'video.publishedAt as publishedAt',
    )
    .where({ concept_ID: { in: conceptIds } })
    .orderBy('video.publishedAt desc')   // newest videos first
    .limit(8 * conceptIds.length);

  // Group + 8-row cap per concept (matches 4.2/4.3 shape).
}
```

**Ordering rationale:** `publishedAt desc` mirrors 4.2's blog-post ordering. Videos are time-sensitive (Developer News from 2024 staler than 2026). Differs from 4.3's `effortLevel asc`.

### Neighborhood enrichment (`srv/knowledge-graph-service.js`)

Phase 4.3 already widened to 3-array merge via the variadic `mergeOtherResources(j, b, m)`. Phase 4.4 adds a 4th branch parallel to the existing 3 and passes the new array:

```javascript
// Phase 4.4 (#447): video overlap rows.
const { Videos, VideoConceptLinks } = cds.entities('com.sap.developers.ims.external');

let videoOtherResources = [];
if (conceptIds.length > 0) {
  const videoOverlaps = await SELECT.from(VideoConceptLinks)
    .columns('video_ID', 'concept_ID')
    .where({ concept_ID: { in: conceptIds } });

  const overlapByVideo = new Map();
  for (const row of videoOverlaps) {
    overlapByVideo.set(row.video_ID, (overlapByVideo.get(row.video_ID) ?? 0) + 1);
  }

  if (overlapByVideo.size > 0) {
    const topVideoIds = [...overlapByVideo.entries()]
      .sort(([, a], [, b]) => b - a)
      .slice(0, MAX_OTHER_RESOURCES)
      .map(([id]) => id);

    const videos = await SELECT.from(Videos)
      .columns('ID', 'slug', 'title', 'url', 'channelTitle', 'publishedAt', 'thumbnailUrl')
      .where({ ID: { in: topVideoIds } });

    const byVideoId = new Map(videos.map((v) => [v.ID, v]));
    videoOtherResources = topVideoIds
      .map((id) => byVideoId.get(id))
      .filter(Boolean)
      .map((v) => ({
        type: 'video',
        slug: v.slug,
        title: v.title,
        url: v.url,
        channelTitle: v.channelTitle,
        publishedAt: v.publishedAt,
        thumbnailUrl: v.thumbnailUrl,
        overlapCount: overlapByVideo.get(v.ID),
      }));
  }
}

// Merge 4 row arrays; top-5 TOTAL across types via variadic helper (4.3's widening).
otherResources = mergeOtherResources(
  journeyOtherResources,
  blogOtherResources,
  missionOtherResources,
  videoOtherResources,
);
```

The `mergeOtherResources` helper from Phase 4.3 (`srv/lib/kg-neighborhood-merge.js`) already supports variadic arrays. **No changes to the helper itself in Phase 4.4** — just pass a fourth array.

### Acceptance criteria

1. **Backfill seeds the corpus.** `node scripts/seed-videos.cjs --months=24 --limit=5000 --commit`:
   - `Videos` ≥ 400 rows (SAP Developers channel has ~400-500 videos in 24mo).
   - `VideoConceptLinks` ≥ 800 rows (budget=5000 × ~2 surviving teaches per video).
   - `VideoServices` ≥ 400 rows (~1 surviving service per video average).
   - Backfill cost: ~$0.18 one-time at gpt-4o-mini rates.

   *Basis:* SAP Developers channel publishes ~3-5 videos/week × 104 weeks ≈ 400-500 videos. Phase 4.3 extraction yielded 2-3 teaches/source at floor 0.6.

2. **Weekly cron is idempotent.** Two consecutive cron runs with no new uploads: `summary.skippedNoChange == fetched`.

3. **Crash-safety holds.** Test-only abort signal between `DELETE links` and `INSERT links` leaves `lastExtractedHash` at its previous value; next cycle re-extracts.

4. **Concept pages render.** A test concept's page on the DEV approuter shows a non-empty "Videos teaching this" section after the seed run + cron has run + content publish. Rows display thumbnail + title + `· by Channel · Date`.

5. **Sidebar shows video rows.** Tutorial-OP sidebar shows at least one `video` row when a tutorial's concepts overlap with at least one indexed video. Top-5 ranking is across all FOUR content types (journey + blog + mission + video).

6. **Telemetry events fire** on click in both surfaces (`kg.video.linked_from_concept_page`, `kg.video.linked_from_sidebar`).

7. **Merge-on-write reuses #707.** A video mentioning a novel concept slug ends up in `Concepts` either as merged-or-minted; `skippedNoEmbed` counts only embed failures.

8. **`featuresService` dedup case-insensitive** (mirrors 4.3). A video description naming "SAP Integration Suite" twice (or "sap integration suite" + "SAP Integration Suite") collapses to one row in `VideoServices`.

9. **MAX-or-abort first-run gate fires.** Calling `runFetchVideos()` against an empty `Videos` table returns `summary.errors > 0` and skips API fetch. Operator gets explicit log: "Videos is empty; refusing to self-bootstrap. Run scripts/seed-videos.cjs first."

### Backfill cost basis

500 videos at gpt-4o-mini (~$0.150 / 1M input, $0.600 / 1M output as of 2026-06):

Per-video: description ~3K chars / 800 input tokens + ~400 output tokens. Total: 500 × (800 × 0.00000015 + 400 × 0.0000006) ≈ **$0.18 one-time**.

Embedding cost: ~10-30 novel concepts × 1 embed call × text-embedding-3-small ≈ $0.001. Negligible.

Steady-state cron (twice-weekly, 5-10 new videos/cycle): ~$0.01/week.

YouTube quota: 1 unit per pagination call. Backfill ≈ 10 units. Steady-state cron ≈ 2 units per cycle. Daily quota is 10K units — well below.
