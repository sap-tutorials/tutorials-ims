## 1. Summary

Phase 4.6 ships SAP-samples GitHub repositories as the **seventh content type** in the knowledge graph, alongside tutorials, learning journeys, blog posts, discovery missions, videos, and api.sap.com api-docs. Each non-archived, non-fork, recently-pushed repo in the `SAP-samples` GitHub org becomes a graph node connected to concepts via a new `embodies` predicate — semantically distinct from `teaches` (samples are working reference implementations, not pedagogy).

The architecture spec called Phase 4.6 "the trickiest semantic last." Three risks the spec flagged: granularity (whole-repo vs per-directory vs per-file), predicate confusion (`embodies` vs `teaches`), and corpus-discovery shape. Brainstorming resolved all three:

1. **Whole-repo granularity** — one graph node per repo. Cleanest chassis fit; ~150-250 nodes expected.
2. **`embodies` predicate** — distinct from `teaches`; section title "Code samples embodying this" reads as "the BTP Workflow sample repo embodies the CAP service handlers concept."
3. **Direct GitHub REST API** — sibling to Phase 4.4's YouTube corpus fetcher. Reuses the existing `GITHUB_TOKEN` from credstore (used by fetch-tutorials).

The architecture lifts the Phase 4 chassis verbatim — schema shape, merge-on-write (#707), crash-safety gate (#708), variadic neighborhood merge (helper unchanged), shared IRI registry, GC iteration, telemetry conventions, AND the #756 `JOB_REGISTRY` chassis — with four structural deltas from prior sub-phases:

1. **GitHub-API-driven corpus discovery** — new `srv/lib/sap-samples-fetcher.js` mirrors `srv/lib/youtube-corpus-fetcher.js`. Native `fetch` against `https://api.github.com/orgs/SAP-samples/repos` with the existing `GITHUB_TOKEN` from credstore.
2. **Auto-filter at fetcher level** — non-archived AND non-fork AND `pushed_at` within 24 months. Reduces ~400 raw repos to ~150-250 quality candidates.
3. **`embodies` predicate** (not `teaches`) — single predicate; one link table (no service-junction sibling like Phase 4.4 had).
4. **Sample-row fields on `OtherResource`** — `language`, `stars`, `lastCommitAt` for sidebar rendering.

Weekly cron at `'43 4 * * 0'` (Sunday 04:43 UTC, off-minute to avoid the existing :00/:13/:23 cluster). MAX-or-abort first-run gate; operator bootstraps via `scripts/seed-samples.cjs --commit` OR the new `seedSamples()` admin action. Concept landing pages get section #7 "Code samples embodying this" between API docs (#6) and Prerequisites. The tutorial-OP sidebar's "Other resources" widens to a 6-array merge.

**The #756 admin Cron health tile picks up the new `fetch-samples` cron automatically** via the `JOB_REGISTRY` chassis. Zero extra wiring; operator gets a Run-now button + JobLastRun history out of the box.

- IRI prefix wiring (`KG_IRI_PREFIXES['sample']` already pre-staked; new `iriSample(slug)` helper; `SHORT_BY_TYPE['sample'] = 'sa'`).
- Projection helper `buildSampleTriples` in `srv/lib/kg-projection.js`.
- GC iteration set extends with `'sample': 'Samples'`.
- `/build/concepts` payload extends with per-concept `samples[]` (8-row cap; `stars DESC, lastCommitAt DESC`).
- Neighborhood enrichment widens to 6-array variadic merge (helper unchanged from Phase 4.3).
- Concept page section #7 "Code samples embodying this" with `Title ↗ · Language · N stars · Updated Jul 2026` row.
- Tutorial-OP sidebar 6th `v-else-if` branch — title + language + stars + lastCommitAt meta.
- Hugo frontmatter pipe-through in `scripts/fetch-concepts.ts`.
- TypeScript `NodeType` widening in BOTH `hugo-apps/src/related-graph/types.ts` and `app/explore/src/types.ts` (12 → 13 types).
- New `formatRelativeMonth(iso)` helper in the existing `related-graph-helpers` module.
- Telemetry events `kg.sample.linked_from_concept_page` + `kg.sample.linked_from_sidebar`.
- Test triad: unit, hybrid (BLOCKED-until-deploy), smoke.

### Out of scope

- Per-directory or per-file graph nodes (whole-repo only per Q1). File-level linking is a future-phase concern; the chassis assumption is "one row per content item."
- README markdown preprocessing — gpt-4o-mini handles raw markdown natively. No HTML stripping, no code-block extraction.
- README full-content storage in HANA — only first 2000 chars (LLM input cap). Larger text doesn't help concept extraction signal.
- Cross-org sample sources (e.g. `sap-tutorials/cloud-cap-samples`) — only `SAP-samples` GitHub org. Other orgs are out of scope (parent issue #447 explicitly limits Phase 4 to SAP-managed content).
- Per-sample fork-of-detection beyond GitHub's `fork: true` flag. Forks are filtered out at the fetcher.
- Star-count threshold filter — too noisy as a quality signal in SAP-samples (some excellent repos have <10 stars; some thin demos have >100). Auto-filter relies on archive/fork/recency only.
- Backfill YAML (unlike Phase 4.5) — GitHub API is reliable; cron self-bootstraps after the first `seed-samples.cjs` run.
- Multi-language support — `language` field is GitHub's primary language string (one value per repo). Secondary languages omitted.
- License badge rendering — kept for v2 if operators ask. Today's design keeps the sidebar tight at `language · stars · lastCommitAt`.

## 3. Architectural decisions (Q1-Q12)

Twelve decisions resolved during brainstorming, with rationale:

| # | Decision | Rationale |
|---|---|---|
| Q1 | **Whole-repo granularity** | Cleanest chassis fit (one row per content item, matching Phase 4.1-4.5). Per-directory breaks chassis (3-10× node explosion); per-file is even worse. ~150-250 repos is a manageable node count. Architecture spec called this the "trickiest semantic" question; resolved cleanly. |
| Q2 | **Predicate `embodies`** (not `teaches`) | Captures the "working reference implementation" semantic. Section title "Code samples embodying this" reads naturally. Architecture spec already named this; lowest design churn. Distinct from `teaches` (tutorials/journeys/missions/videos), `discusses` (blogs), `officialReferenceFor` (api-docs). |
| Q3 | **Direct GitHub REST API** | `srv/lib/sap-samples-fetcher.js` mirrors Phase 4.4's `youtube-corpus-fetcher.js`. Reuses existing `GITHUB_TOKEN` from credstore. 5000 req/hr quota easily covers a weekly catalog refresh. Most control vs MCP-wrapped `getSamples` (TODO-throw today). |
| Q4 | **Auto-filter: non-archived + non-fork + <24mo-stale** | Reduces ~400 raw repos to ~150-250 quality candidates. No per-repo curation (no opt-in allowlist). Star threshold rejected as too noisy. |
| Q5 | **Weekly Sunday 04:43 UTC** (`'43 4 * * 0'`) | Off-minute :43 avoids the :00/:13/:23 cluster. SAP-samples catalog drift is slow-to-moderate; weekly is the right cadence band between Phase 4.4's twice-weekly and 4.5's monthly. |
| Q6 | **Metadata + README first 2000 chars** as LLM input | README lead paragraphs are where SAP-samples authors describe what the repo demonstrates. 2000 chars is the sweet spot for signal vs cost. Metadata-only under-extracts; first-3-files over-pays. |
| Q7 | **Sample fields: `language` + `stars` + `lastCommitAt`** | Three short/numeric fields; tight sidebar row. Language tells the user "is this my stack"; stars gives a quality signal; lastCommitAt signals freshness. License rejected as too verbose for v1. |
| Q8 | **Section #7 with `↗` link-out icon** | Inserted between Official reference documentation (#6) and Prerequisites. Row shape: `Title ↗ · Language · N stars · Updated Jul 2026`. Reuses the Phase 4.5 `.kg-link-out` CSS class. Monospace `.kg-language` badge mirrors Phase 4.5's `.kg-api-type`. |
| Q9 | **TTL 365 days** (arch-spec default) | Pre-staked in `srv/lib/external-content-ttl.js` as `'sample': 365`. Aggressive enough to drop archived repos within a year; not so aggressive that brief cron outages empty the catalog. Aligns with SAP-samples maintenance lifecycle. |
| Q10 | **Sort by `stars DESC, lastCommitAt DESC`** | Concept page shows most-starred / most-recently-updated first. No visual stale-treatment for v1 (a "Stale" badge could be added in v2 if operators request). Sort keys server-side in `/build/concepts` payload. |
| Q11 | **Reuse existing `GITHUB_TOKEN`** | Already in credstore for fetch-tutorials. Authenticated quota of 5000 req/hr easily covers ~500 calls/cycle. Unauth (60/hr) is risky — would burn shared quota if other CF instance hits GitHub. |
| Q12 | **Chassis defaults: MAX-or-abort + telemetry + admin action** | Same pattern as Phase 4.4/4.5 baseline. Operator triggers seed via CLI or admin button. The admin `seedSamples()` action emits ONE `SecurityEvent` (action=`kg.samples.seed`). The cron itself emits the standard #756 chassis lifecycle events (`cron.manual-trigger.started` + completion) when `runJobByName('fetch-samples', {manualTrigger: true})` fires. Net audit emissions per admin-button click: typically 3 (1 admin + 2 cron lifecycle). The new `fetch-samples` cron automatically gets a Run-now button on the admin Cron health tile via the #756 chassis. |

## 4. Architecture

### 4.1 Data model

Two new entities under namespace `com.sap.developers.ims.external` in `db/external-content.cds`:

```cds
// Phase 4.6 (#747): SAP-samples GitHub repositories as graph nodes.
// One row per repo (whole-repo granularity per spec §3 Q1).
// Spec: docs/superpowers/specs/2026-06-29-747-phase4.6-code-samples.md
entity Samples : cuid, managed {
  slug              : String(120) @assert.unique;     // 'sa-<org>__<repo>'
  title             : String(255);                    // repo full_name or display label
  description       : LargeString;                    // README first 2000 chars (NCLOB — see §10.1)
  url               : String(500);                    // https://github.com/<org>/<repo>
  sourceId          : String(120);                    // <org>/<repo> (e.g. 'SAP-samples/cloud-cap-samples')
  contentHash       : String(64);                     // SHA-256(description+language+lastCommitAt+stars+sorted(topics))
  lastExtractedHash : String(64);                     // #708 crash-safety gate
  firstSeenAt       : Timestamp @cds.on.insert: $now;
  lastSeenAt        : Timestamp;
  pinUntil          : Timestamp;                      // chassis admin override

  // Sample-specific:
  language          : String(40);                     // GitHub primary language
  stars             : Integer;                        // star count at last fetch
  lastCommitAt      : Timestamp;                      // GitHub pushed_at

  links             : Composition of many SampleConceptLinks on links.sample = $self;
}

entity SampleConceptLinks : cuid, managed {
  sample       : Association to Samples @assert.notNull;
  concept      : Association to ims.Concepts @assert.notNull;
  predicate    : String(40);                          // 'embodies'
  confidence   : Decimal(3, 2);                       // LLM floor 0.7
  extractedAt  : Timestamp;
  modelVersion : String(40);
}

annotate SampleConceptLinks with
  @assert.unique.sampleConcept : [sample, concept, predicate];
```

**Slug format:** `sa-<canonicalizedSourceId>` where `canonicalizeSourceId` lowercases, normalizes `/` to `__` FIRST (preserves the org/repo separator), then replaces all remaining non-`[a-z0-9_]` chars (including dashes and dots) with `_`. GitHub repo names allow dots and dashes; for `SAP-samples/sap.s4hanaonpremise.foo` the canonical slug is `sa-sap_samples__sap_s4hanaonpremise_foo`. Slug is case-stable; equality checks use `LOWER(slug)`.

**`description: LargeString` (NCLOB)** — README first 2000 chars trimmed at the fetcher. Same Phase 4.4/4.5 LOB-locator mitigation rule: never SELECT description alongside non-LOB metadata via CDS QL. Four read sites verified:
1. Cron upsert path: pulls only `ID/contentHash/lastExtractedHash`
2. `buildSampleTriples` in `kg-projection.js`: omits description
3. `published-concepts-query.js` payload: omits description
4. Neighborhood enrichment: omits description

### 4.2 Corpus fetcher

`srv/lib/sap-samples-fetcher.js` — sibling to `youtube-corpus-fetcher.js`. Module-singleton state via `globalThis Symbol`. Test seam: `_setMockFetcher` + `_resetForTests`.

**Public API:**

```javascript
const ORG = 'SAP-samples';
const PAGE_SIZE = 100;
const MAX_PAGES = 30;                                       // safety backstop (3000-repo cap)
const STALE_CUTOFF_MS = 24 * 30 * 24 * 60 * 60 * 1000;     // 24 months
const PER_PAGE_TIMEOUT_MS = 30_000;

/**
 * @typedef {Object} SampleCorpusRow
 * @property {string} sourceId       — '<org>/<repo>'
 * @property {string} title
 * @property {string} description    — README first 2000 chars (or fallback: repo.description)
 * @property {string} url            — https://github.com/<org>/<repo>
 * @property {string} language       — GitHub primary language
 * @property {number} stars
 * @property {string} lastCommitAt   — ISO timestamp from pushed_at
 * @property {string[]} topics
 */

export async function fetchSapSamplesCorpus({
  seenSourceIds = null,
  limit = 500,
  apiKey = null,
} = {}) { ... }
```

**Filter rules** (per Q4):
- `repo.archived === false`
- `repo.fork === false`
- `Date.now() - Date.parse(repo.pushed_at) < STALE_CUTOFF_MS` (24 months)

**API calls per cycle:**
- 1 paginated listing per page × ~3 pages = ~3 calls (250 repos / 100 per page)
- 1 README fetch per filter-passing repo = ~150-250 calls
- **Total: ~250-500 calls/cycle.** 5000 req/hr authenticated quota → easily under 10%.

**README fallback:** if `GET /repos/<org>/<repo>/readme` returns 404, fall back to `repo.description`. If both empty, skip the repo (no LLM signal).

**Auth:** `Authorization: Bearer ${apiKey}` header. The cron resolves `apiKey` via `resolveSecret('TUTORIALS_GITHUB_TOKEN', { logTag: 'fetch-samples' })` — the canonical credstore key (per `scripts/seed-secrets.cjs:98`). For local dev / hybrid testing, env-var fallback to `GITHUB_TOKEN` matches the existing fetch-tutorials behavior (`scripts/parsers/github.ts:205`). Anonymous mode aborts cycle with `summary.errors++` + log.

**Pagination + retry:**
- 30-page safety backstop
- Native `fetch` only
- `AbortSignal.timeout(30_000)` per page
- 403 with `X-RateLimit-Remaining: 0` → log + bubble (cron aborts cycle; retry next Sunday)

### 4.3 LLM extraction adapter

`srv/lib/sample-extract.js` — single-predicate sibling to `srv/lib/api-doc-extract.js`. Uses shared `extractConceptsCore({system, user, schema, callModel})`.

**System prompt** captures the `embodies` semantic:

> You are extracting concepts from an SAP-samples GitHub repository. The repo is a **working reference implementation** — it EMBODIES one or more concepts via actual code.
>
> Identify the technical concepts this sample embodies. Aim for 2-5 concepts. Each concept comes with:
>   - slug: stable kebab-case identifier. Reuse from REGISTRY HINT when fits.
>   - name: human-readable label. REQUIRED.
>   - confidence: 0.0-1.0; floor 0.7.
>
> Do NOT include concepts the README merely mentions in passing. Only emit a concept when this repo is a working demonstration of how to USE that concept.
>
> You will be given a K=25 list of registry concepts + the repo's primary language + GitHub topics. STRONGLY PREFER reusing a registry slug.

**Output schema** (single predicate):

```json
{
  "embodies": [
    { "slug": "cap-service-handlers", "name": "CAP service handlers", "confidence": 0.92 }
  ]
}
```

**Post-validation rules:**
- `confidence ≥ 0.7`
- `name` required, length ≥ 2 chars
- Cap 6 concepts per repo (extras silently dropped)
- Slugs canonicalized to lowercase kebab-case

### 4.4 Weekly cron

`srv/jobs/fetch-samples-job.js` — clones `srv/jobs/fetch-videos-job.js`. Counter shape uses `linksWritten` (matches Phase 4.5 precedent; predicate is `embodies`, not `teaches`).

**Registered via #756 `registerJob` chassis** in `srv/jobs/scheduler.js`:

```javascript
// Phase 4.6 (#747): weekly SAP-samples corpus refresh + concept-link extraction.
registerJob({
  jobName: 'fetch-samples',
  schedule: '43 4 * * 0',                  // Sunday 04:43 UTC
  ttlMs: 30 * 60 * 1000,
  description: 'Fetch SAP-samples GitHub repos + extract embodies concepts (weekly)',
  fn: async () => {
    const { runFetchSamples } = await import('./fetch-samples-job.js');
    return runFetchSamples();
  },
});
```

The chassis automatically:
- Writes `JobLastRun` rows on every cycle (success/error/lockheld) — #756 retrofit
- Surfaces a Run-now button on the admin Cron health tile — #756 admin UI
- Pre-seeds a `JobLastRun` row at boot via `cds.on('served')` — #756 chassis

**Cron flow** (mirrors Phase 4.4 + 4.5 verbatim, simplified):

1. **Budget gate** — `ChatSettings.samplesExtractBudgetPerCycle` (default 50) via try/catch; absent column → default.
2. **API-key resolution** — `resolveSecret('TUTORIALS_GITHUB_TOKEN', { logTag: 'fetch-samples' })` (canonical credstore key; env-var fallback to `GITHUB_TOKEN` for hybrid dev). Abort cycle if missing.
3. **MAX-or-abort first-run gate** — `SELECT MAX(lastSeenAt) FROM Samples`. If empty AND no `sinceIsoOverride`: ABORT with `summary.errors++` + log:
   > `fetch-samples: Samples is empty; refusing to self-bootstrap. Run scripts/seed-samples.cjs --commit first (or click 'Seed samples' in admin UI).`
4. **Merge config** — `mergeThreshold` + `embeddingModel` via `resolveKnowledgeGraphSettings`.
5. **Load concept registry** — `loadConceptRegistry(db)`.
6. **Fetch corpus** — `fetchSapSamplesCorpus({ apiKey, seenSourceIds })`. Returns auto-filtered rows.
7. **Per-repo upsert** —
   - `slug = 'sa-' + canonicalizeSourceId(row.sourceId)`
   - `contentHash = sha256(description + language + lastCommitAt + stars + sorted(topics).join(','))`
   - UPSERT via `SELECT id WHERE LOWER(slug)=?` → INSERT-or-UPDATE
   - Existing row read pulls ONLY `ID`, `contentHash`, `lastExtractedHash` (LOB-locator mitigation)
8. **Per-repo extract gate** — skip if contentHash unchanged AND lastExtractedHash matches contentHash. Increment `skippedNoChange`.
9. **Budget gate** — if `summary.extracted >= budget`, set `budgetExhausted: true` and skip extraction (upsert already happened).
10. **Extract concept links** — `extractConceptsFromSample({ title, description, language, topics, registry })`.
11. **Merge-on-write** — `resolveConceptCandidates` with FULL 6-arg signature. Returns `{ resolved, pendingMints, counters }` (#707 chassis).
12. **Mint pendingMints first** — INSERT into `Concepts` BEFORE writing `SampleConceptLinks` rows (FK targets). Match Phase 4.4/4.5 pattern.
13. **Link table writes** — `SampleConceptLinks` rows. Dedup by `(sample_ID, concept_ID, 'embodies')`.
14. **`lastExtractedHash` UPDATE as FINAL step** — #708 crash-safety. Last write per repo.

**Summary counters** (shape matches Phase 4.5; `linksWritten` not `teachesWritten`):

```javascript
{
  fetched, upserted, extracted, skippedNoChange,
  mergedAtExtract, mintedAtExtract, skippedNoEmbed, linksWritten,
  promptTokens, completionTokens, errors, budgetExhausted,
}
```

**Test injection seams:** `embed`, `extractFn`, `budgetOverride`, `sinceIsoOverride`, `apiKeyOverride`.

```javascript
this.on('seedSamples', async (req) => {
  const commit = !!req.data?.commit;
  if (!commit) {
```

### 4.7 `runJobByName` chassis extension

The #756 `runJobByName(jobName, opts)` currently accepts `{manualTrigger, user}` and invokes `runWithLock` which calls `fn(logId)`. Phase 4.6's `seedSamples` action needs to pass `sinceIsoOverride` + `budgetOverride` through to the cron fn. Plan Task 2 ships a small extension that **preserves the existing `(logId)` first positional arg** for the 4 logId crons and passes opts as a SECOND positional arg:

```javascript
// srv/jobs/scheduler.js
export async function runJobByName(jobName, opts = {}) {
  const job = JOB_REGISTRY.get(jobName);
  if (!job) throw new Error(`Unknown jobName: ${jobName}`);
  // #747: thread logId AND opts through. The 4 logId crons consume the
  // first positional; new crons that need overrides consume the second.
  // Existing cron fns that take zero or one arg ignore the second.
  return runWithLock(job.jobName, job.ttlMs, (logId) => job.fn(logId, opts), opts);
}
```

**Backward-compat:** the 4 logId crons (`ngds-retry`, `account-merge-batch`, `runReconciliationJob`, `runContributorNotificationsCycle`) currently declare `fn: (logId) => retryNgds(logId)` etc. After this change, JS invokes `((logId) => retryNgds(logId))(logId, opts)` — the arrow function ignores the second arg. No change to those cron fns.

The 18 eager-no-logId crons (e.g. `cleanup-step-failures` with `fn: () => cleanupStepFailures(90)`) similarly ignore both args.

The 3 lazy-import crons (`fetch-discovery-missions`, `fetch-videos`, `fetch-api-docs`) currently take zero args; their fn becomes `async (_logId, _opts) => { ... }` which ignores both. No change to their bodies.

**Only Phase 4.6's `runFetchSamples` consumes the opts:**

```javascript
// srv/jobs/fetch-samples-job.js
export async function runFetchSamples(logId, opts = {}) {
  const { sinceIsoOverride, budgetOverride, embed, extractFn, apiKeyOverride } = opts;
  // ... cron flow uses these overrides ...
}
```

**Verified `runWithLock` line 116** at `srv/jobs/scheduler.js`: `result = await fn(logId);` — calls fn with exactly one arg today. Phase 4.6 changes the LAMBDA `runWithLock` invokes to `(logId) => job.fn(logId, opts)`, which still passes `logId` through. Zero existing cron breaks.

### 4.8 Projection helper

`srv/lib/kg-projection.js` — `buildSampleTriples({samples, links})`. Mirrors `buildVideoTriples` (the canonical Phase 4.4 helper-shape using `triple()`, `literalTriple()`, `iri()`, `iriPredicate()`):

```javascript
export function buildSampleTriples({ samples = [], links = [] } = {}) {
  const triples = [];
  const visibleSampleSlugs = new Set();

  for (const s of samples) {
    if (!s || !s.slug) continue;
    if (!isWithinTTL('sample', s.lastSeenAt)) continue;
    visibleSampleSlugs.add(s.slug);
    const subj = iriSample(s.slug);
    triples.push(triple(iri(subj), iri(RDF_TYPE), iri(KG_SAMPLE)));
    triples.push(literalTriple(iri(subj), iriPredicate('title'), s.title ?? ''));
    triples.push(literalTriple(iri(subj), iriPredicate('slug'), s.slug));
    if (s.language) {
      triples.push(literalTriple(iri(subj), iriPredicate('language'), s.language));
    }
    if (s.stars != null) {
      triples.push(literalTriple(iri(subj), iriPredicate('stars'), String(s.stars)));
    }
    if (s.lastCommitAt != null) {
      triples.push(literalTriple(iri(subj), iriPredicate('lastCommitAt'),
        s.lastCommitAt instanceof Date ? s.lastCommitAt.toISOString() : String(s.lastCommitAt)));
    }
  }

  for (const link of links) {
    if (!link || !link.sampleSlug || !link.conceptSlug) continue;
    if (!visibleSampleSlugs.has(link.sampleSlug)) continue;
    triples.push(triple(
      iri(iriSample(link.sampleSlug)),
      iriPredicate(link.predicate || 'embodies'),
      iriConcept(link.conceptSlug)
    ));
  }

  return triples;
}
```

## 7. Operational concerns

### 7.1 Seed corpus content

The catalog is GitHub-API-discovered, not hand-curated. Phase 4.6 does NOT ship a YAML seed file (unlike Phase 4.5). The auto-filter rules in §4.2 are deterministic; whatever passes them at first cron fire becomes the catalog.

Expected first-seed corpus size: **~150-250 repos**. Verify by:

```bash
  "https://api.github.com/orgs/SAP-samples/repos?per_page=100&type=public" | \

```

### 7.2 Cost ceiling estimate

| Stage | LLM cost | GitHub API quota |
|---|---|---|
| Seed CLI | $0 (no LLM in CLI itself — invokes cron runner) | $0 (cron handles all calls) |
| First cron cycle (~250 repos) | ~$0.40 one-time | ~500 calls (10% of 5000/hr) |
| Steady-state weekly | ~$0.02 (~10 new/changed) | ~50-100 calls/cycle |
| GC cron | $0 | $0 (DB-only) |

No image processing, no transcript fetch. Pure text extraction.

### 7.3 Concurrency safety

The seed CLI + the cron + the admin "Seed samples" action all share `runWithLock('fetch-samples', ...)` (via the #756 chassis path). The first to acquire wins; subsequent invocations return `{skipped: true, reason: 'lock-held'}`.

Lock TTL: 30 minutes (sized for largest plausible run — first seed of ~250 repos).

### 7.4 GitHub API failure handling

- **403 with `X-RateLimit-Remaining: 0`** — quota exhausted. Cron aborts with clear log. Retry next Sunday. 5000 req/hr quota is well-padded; this should never fire under normal use.
- **401 Unauthorized** — token invalid or revoked. Distinct log line (`TUTORIALS_GITHUB_TOKEN appears invalid (401 from GitHub)`) so operators don't confuse it with quota exhaustion. Cron aborts.
- **404 on README fetch** — fetcher falls back to `repo.description`. If that's also empty, the repo is skipped (no LLM signal).
- **5xx Server Error** — transient GitHub outage. Logs as `summary.errors++` and skips that page; cron continues with remaining pages so a single page failure doesn't crash the cycle.
- **Network timeout** — `AbortSignal.timeout(30_000)` per page; errors bubble to cron orchestrator; `summary.errors++`. Cron continues with remaining pages.
- **Total cycle failure** (e.g. GitHub down) — cron returns `summary.errors > 0`; #756 chassis writes `JobLastRun.lastErrorAt + lastErrorMessage`. Admin sees the failure on the next tile load.

### 7.5 Repo without README

Phase 4.6 fetcher falls back to `repo.description` (the short GitHub description, always present). If both README and description are empty, the repo is skipped — no signal for LLM extraction. Edge case; SAP-samples repos almost always have a README.

## 10. Gotchas & operational notes

### 10.1 HANA LOB-locator on `description`

`Samples.description` is `LargeString` (NCLOB). Same Phase 4.4/4.5 LOB-locator mitigation rule: never SELECT it alongside non-LOB metadata via CDS QL. **Four read sites** in this phase MUST omit description:

| Site | Mitigation |
|---|---|
| Cron upsert path (existing-row read) | Pulls only `ID/contentHash/lastExtractedHash` |
| `kg-projection.js` `loadFixtures` | Omits description |
| `published-concepts-query.js` payload | Omits description (column list at §4.9) |
| `kg-neighborhood-merge.js` enrichment | Omits description |

Fresh description always comes from the GitHub README fetch, never from HANA mid-cycle.

### 10.2 Slug case canonicalization

`Samples.slug` is lowercase. The seed loader + cron canonicalize `sourceId` from GitHub's `<org>/<repo>` format:
- `SAP-samples/cloud-cap-samples` → `sa-sap_samples__cloud_cap_samples`
- `SAP-samples/sap.s4hanaonpremise.foo` → `sa-sap_samples__sap_s4hanaonpremise_foo`

Implementation: `s.toLowerCase().replace(/\//g, '__').replace(/[^a-z0-9_]/g, '_')`. The slash → `__` step runs FIRST to preserve the org/repo separator; subsequent regex replaces dashes + dots + every other non-alphanumeric character with single underscore.
- Both seed loader and cron use canonical `SELECT id FROM table WHERE LOWER(slug) = ?` lookup.

### 10.3 `runJobByName` opts pass-through

The #756 chassis was shipped with `{manualTrigger, user}` opts. Phase 4.6 extends to also forward `sinceIsoOverride` + `budgetOverride` to the cron fn. The chassis change is backward-compat: existing eager-import cron fns ignore the opts arg; only Phase 4.6's `runFetchSamples({sinceIsoOverride, budgetOverride})` consumes them.

### 10.4 GitHub README markdown

LLM extraction operates on raw markdown — no preprocessing. gpt-4o-mini handles markdown syntax natively (headers, code blocks, links, tables). The 2000-char truncation is a hard cap; if a README header takes 200 chars and the lead paragraph takes another 1500, we have ~300 chars of body context. Acceptable for concept extraction.

### 10.5 `srv-qa` cp list

If any new module under `srv/lib/` is added (it is — `sap-samples-fetcher.js`, `sample-extract.js`), re-walk transitive `./` imports from `srv/lib/content-store.js` and verify every dependency is in `.deploy/mta.yaml`'s `srv-qa` `cp` list. Missing deps crash QA boot at MTA deploy time.

### 10.6 CAP 10 readiness

Phase 4.6 inherits the CAP 10 compatibility audit performed in 4.1-4.5. No new compat flags used; no removed flag references introduced.

### 10.7 Bootstrap MAX-or-abort interaction with Helm/MTA deploy

First deploy of Phase 4.6 to a fresh subaccount lands the schema + cron registration with an empty `Samples` table. The very next Sunday would hit the MAX-or-abort gate and abort with a log line — no data loss, just a skipped cycle.
