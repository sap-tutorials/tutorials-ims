## 1. Goal

Surface SAP community events — CodeJams, Devtoberfest, TechEd, User Groups — as first-class nodes in the knowledge graph so concept pages and the tutorial-OP sidebar can answer "there is a hands-on workshop covering this in Berlin next month."

Reuses Phase 4.1–4.7 chassis verbatim: shared `db/external-content.cds`, `PER_TYPE_TTL_DAYS` registry, `KG_IRI_PREFIXES` registry, `RESOURCE_TYPE_CONFIG`, `JOB_REGISTRY`, MAX-or-abort first-run gate, `#708` crash-safety, `#707` merge-on-write, `#756` admin-triggered "Run now" button.

## 2. Decisions on the issue's 5 open questions

| # | Question | Decision | Why |
| --- | --- | --- | --- |
| 1 | Event scope on ship | **All types the source exposes** (`codejam`, `devtoberfest`, `teched`, user groups when added upstream) with a `source` discriminator column | Row shape is uniform per upstream, so the "widen later" savings are token-thin — one nullable column. TechEd cardinality is low (per-conference, not per-session), so it does not swamp the graph. |
| 2 | Past vs upcoming | **Decay via `endDate + 30d`**, no archive branch | The `endDate` grace path in `isWithinTTL` already exists and is untested only because 4.3 deferred trials; 4.8 is where it earns its keep. Past-event recordings live under the video corpus (4.4), not the event corpus. |
| 3 | Capacity refresh cadence | **No capacity modelling at all** | The upstream payload from `search_events`, Khoros, and RSS carries no seats / registration-status field. The issue's green/amber/red badge is not backed by data on the wire. Deferred until we have a source. |
| 4 | Registration link target | **Use the source's `url` verbatim** | Khoros returns the canonical community.sap.com event page; RSS returns the source URL directly. No translation table, no `developers.sap.com` remap. |
| 5 | Geographic personalization | **Out of scope in 4.8; schema is ready** | `location` + `scope` + `virtualOrInPerson` columns store enough for future `Users.region` matching; extraction pipeline ignores geo. Phase 4.9+ ships the profile side. |

## 3. Fetch strategy — vendored port, no MCP dependency

**Decision:** Do NOT call `sap-devs-server` MCP `search_events`. Reimplement the Khoros + RSS fetchers in JS inside this project.

**Why:** Prior sub-phases learned this lesson twice already (`sap-devs-learning.js`, `sap-devs-discovery.js` are vendored ports of the Go originals — same public-endpoint calls, no MCP round-trip). The MCP transport was never wired into the deployed CF container per the header comment in `srv/lib/sap-devs-client.js`. Adding a new corpus behind an unreliable transport is a known-bad path.

**Source of truth being ported:**
- `D:\projects\sap-devs-cli\internal\events\khoros.go` — Khoros community-groups API for CodeJams (128 lines)
- `D:\projects\sap-devs-cli\internal\events\rss.go` — generic RSS feed reader for Devtoberfest (79 lines)
- `D:\projects\sap-devs-cli\internal\content\events.go` — deduplication / query filter helpers (62 lines)
- `D:\projects\sap-devs-cli\content\packs\base\event-types.yaml` — event-type registry (endpoints, board IDs, scope defaults)

Total surface to port: ~270 lines of Go → ~350 lines of JS across two files (`srv/lib/events/khoros-fetcher.js`, `srv/lib/events/rss-fetcher.js`) plus a tiny orchestrator (`srv/lib/events/index.js`) mirroring `srv/lib/help-docs/index.js` from 4.7.

Event-type registry is inlined in `srv/lib/events/index.js` as a small `const EVENT_TYPES` array (three entries today: `codejam` khoros / `teched` manual / `devtoberfest` rss). YAML seed is unnecessary — the registry is small and stable.

**No `sap-devs-client.js` changes.** The events fetcher is a peer of `srv/lib/help-docs/`, not a new MCP tool. This is the cleanest fit for Tom's guidance ("have the logic directly in this project").

## 4. Schema (`db/external-content.cds` addition)

### Name collision

`db/schema.cds:227` already declares `entity Events` (mission-attendance / event-scoring — `Missions.event`, `PrizeRecords.event`, `TaskRecords.event` all associate to it). **Cannot reuse the name.**

**Chosen name:** `CommunityEvents` + `CommunityEventConceptLinks`. Rejected: `ExternalEvents` (already implicit — the file is `external-content.cds`), `CodeJams` (too narrow now that scope covers Devtoberfest and TechEd).

### Entity shape

```cds
// Phase 4.8 — SAP community events (CodeJams, Devtoberfest, TechEd, User Groups)
entity CommunityEvents : cuid, managed {
  slug              : String(80) @assert.unique;   // 'ce-' + kebab(sourceId), 60-char truncated
  eventType         : String(20);                  // 'codejam' | 'teched' | 'devtoberfest' | 'usergroup'
  source            : String(20);                  // 'khoros' | 'rss' | 'manual'
  title             : String(500);
  description       : LargeString;                 // synthesized from title + location + type if upstream provides none
  url               : String(1000);
  sourceId          : String(200);                 // upstream id (e.g. 'codejam/12345')
  location          : String(500);                 // free-form; 'virtual' sentinel value handled
  scope             : String(20);                  // 'local' | 'regional' | 'virtual' | 'global'
  virtualOrInPerson : String(20);                  // 'virtual' | 'in-person' (derived from location and scope)
  startDate         : Date;                        // upstream 'date' — required
  endDate           : Date;                        // upstream 'end_date' — nullable for single-day events
  contentHash       : String(64);
  lastExtractedHash : String(64);                  // #708 crash-safety gate — set AFTER links persist
  firstSeenAt       : Timestamp @cds.on.insert: $now;
  lastSeenAt        : Timestamp;
  pinUntil          : Timestamp;                   // manual pin override for GC
  links             : Composition of many CommunityEventConceptLinks on links.event = $self;
}

entity CommunityEventConceptLinks : cuid {
  event        : Association to CommunityEvents @assert.notNull;
  concept      : Association to ims.Concepts;
  predicate    : String(20);                       // 'covers'
  confidence   : Decimal(3, 2);
  snippet      : String(200);                      // denormalized at INSERT (title + location)
  extractedAt  : Timestamp;
  modelVersion : String(40);
  @assert.unique.pair : [event, concept];
}
```

### Predicate

**`covers`** (matches the issue's suggestion and the `learning-journey/covers/concept` semantic from 4.1). Avoids overloading `teaches` (already used by `discovery-mission` and `video`) — differentiating the RDF predicate keeps per-corpus SPARQL filterable.

### Fields intentionally NOT added

- **`capacityStatus`** — not in the upstream payload. See §2 Q3.
- **`registrationStatus`** — same reason.
- **`sampleRepoUrl` / `videoUrl`** — cross-pollination with 4.4 (`Videos`) and 4.6 (`Samples`) happens through the shared `Concepts` graph, not new columns. If an event links to the same concept as a video, both surface in the concept page's respective sections.
- **`region` / `country` / `city`** — free-form `location` is sufficient for 4.8. Structured geo requires a parser and a controlled vocabulary; deferred to Phase 4.9+ when `Users.region` lands.

## 6. Cron job (`srv/jobs/fetch-community-events-job.js`)

Template mirrors `srv/jobs/fetch-help-docs-job.js` step-for-step.

### Schedule

**`31 4 * * 1,4`** (Mon+Thu 04:31 UTC). Twice-weekly, off-minute matching scheduler.js convention.

Rationale: event lifecycle is weeks-to-months, so a weekly cadence is coarse enough to miss registration-opens; daily is unnecessarily aggressive given the client-side 6h cache on external fetches. Mon+Thu keeps developers who plan on weekends fresh on either side.

Registered in `JOB_REGISTRY` (`srv/jobs/scheduler.js`) so the admin "Run now" button auto-appears per the #756 chassis.

### Flow

1. Budget resolution via `ChatSettings.communityEventsExtractBudgetPerCycle` (default 200)
2. Merge config (`mergeThreshold`, `embeddingModel`)
3. Registry load
4. MAX-or-abort first-run gate — refuses to run if `MAX(lastSeenAt)` is empty on `CommunityEvents`
5. Fetch corpus via `srv/lib/events/index.js` orchestrator (Khoros + RSS, deduped by `sourceId`)
6. LOB-safe metadata pull; per-row upsert
7. `#708` crash-safety extract gate
8. Budget gate
9. Embed description + K=25 nearest concepts
10. LLM extraction (single predicate `covers`, no anchor field)
11. `resolveConceptCandidates` → `{resolved, pendingMints, counters}`
12. INSERT `pendingMints` into Concepts (FK targets first)
13. DELETE prior `CommunityEventConceptLinks`; INSERT new set with denormalized `snippet`
14. FINAL step per row: `lastExtractedHash` UPDATE (crash-safety close)

Description synthesis for rows lacking one (Khoros items where `subject` is the only content): `"${title} — hands-on ${eventType} in ${location} on ${startDate}"`. Deterministic (same title/location → same synthesized description → stable `contentHash`).

## 7. GC (`srv/jobs/gc-external-content-job.js`)

Add `CommunityEvents` to `ITERATION_SET` with content-type key `'community-event'`. **Route through the existing reserved date-aware branch** (line 49-54 TODO for trials). Pass `endDate` to `isWithinTTL`. Rows past `endDate + 30d` get pruned; composition cascades delete link rows.

For rows where `endDate` is null (single-day events), the sweep uses `startDate` as `endDate` — same 30-day grace after the day of the event.

No sibling-association sweep needed (no back-refs to CommunityEvents from other entities).

## 8. Seed CLI (`scripts/seed-community-events.cjs`)

Mirrors `scripts/seed-help-docs.cjs`. `--dry-run` default (budget=0, no LLM calls, verifies schema + fetcher wiring), `--commit` for real seed. Bypasses MAX-or-abort via `sinceIsoOverride: '1970-01-01T00:00:00Z'` + `manualTrigger: true`.

Runbook line for `CLAUDE.md` or the phase-4.8 PR body:

```bash
node scripts/seed-community-events.cjs --commit
```

## 9. Concept-page section

Insert as **section #10 in `hugo/layouts/concepts/single.html`** (after Samples #9, before Prerequisites). `data-kg-section="community-events"`. Section renders when `.Params.communityEvents` is non-empty (Hugo `{{ with }}` pattern).

Data pipeline:
1. `srv/lib/published-concepts-query.js` gains a `communityEvents` sub-query per concept (returns projected events within TTL, sorted by `startDate` ascending, max 5 per concept — same shape as the other 4.x corpora).
2. `scripts/fetch-concepts.ts` emits `communityEvents` in the per-concept frontmatter.
3. Hugo layout renders per-row: `<a href={url}>{title}</a> · {location} · {startDate}{virtual ? ' · 🌐' : ''}`.

Section priority ordering (spec §5 of the Phase 4 arch): Events land at #10 because they are lifecycle-bound and thus lower-value-per-view than durable narrative content (docs, journeys). Above Prerequisites because concept-page structural sections group last.

## 13. Deferrals (explicit non-goals for 4.8)

- **Capacity / registration-status badge.** Not in upstream payload.
- **Geographic personalization** (`Users.region`, "events near you" filter). Deferred to Phase 4.9+.
- **User-group event source.** Adding a Khoros board id / RSS feed for user groups is a one-line addition to `EVENT_TYPES` in `srv/lib/events/index.js`; ship when the source URL is confirmed.
- **Cross-corpus enriched surfaces** (e.g. "event + its sample repo + its recording" grouped on the concept page). Shared-concept join already exposes this implicitly; a curated widget is a follow-up.
- **YAML curated seed.** Upstream Khoros + RSS is authoritative; cron self-repairs.
- **Vendored port of `search_events` MCP tool.** Fetchers are direct-to-source; the MCP wrapper is not part of this project.

## 14. Success criteria

- CDS schema deploys clean on DEV; `CommunityEvents` + `CommunityEventConceptLinks` visible in HANA catalog.
- Seed CLI (`--commit`) produces ≥5 rows in `CommunityEvents` and ≥5 rows in `CommunityEventConceptLinks` against DEV.
- Concept page for at least one seeded concept renders the new "Upcoming hands-on events" section.
- Tutorial-OP sidebar shows a `community-event` row for at least one tutorial whose concepts overlap the seeded events.
- GC prunes rows past `endDate + 30d` (verified with a `pinUntil`-past-then-clear hybrid test).
- All unit + hybrid tests green; smoke suite green post-deploy.
