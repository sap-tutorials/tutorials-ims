## Summary

Phase 4.1 ships **Learning Journeys** as the first new graph node type under the Phase 4 architecture chassis. A weekly cron fetches journey metadata from the `sap-devs` MCP server, scrapes the full journey body from `learning.sap.com` (with tiered fallback), extracts `covers` (journey → concept) and `journeyPrerequisite` (journey → journey) relations via the refactored LLM extractor, and surfaces journeys on Phase 3's concept landing pages + a new "Other resources" section on the tutorial-OP sidebar.

4.1 also lands **five chassis-level obligations** (per arch §6.2.1) that 4.2-4.6 will depend on: the shared `sap-devs-client.js` MCP wrapper, the `external-content-ttl.js` helper, the cross-type GC cron, the `/graph/neighborhood` `otherResources` response-shape extension, and the new `db/external-content.cds` schema file.

## Scope

### In scope

- **`LearningJourneys`, `LearningJourneyConceptLinks`, `LearningJourneyPrerequisites`** as first-class CDS entities (3 new tables; ~50 LoC schema).
- **Tiered body-fetcher** (`structured` → `readability` → `metadata` fallback) for `learning.sap.com` scraping; per-tier counts logged for monitoring.
- **`extractConceptsFromLearningJourney`** per-type adapter calling the refactored `extractConceptsCore`. Two predicates: `covers` (confidence floor 0.6) + `journeyPrerequisite` (confidence floor 0.7).
- **Weekly cron** `fetch-learning-journeys-job.js` at `13 3 * * 0` (Sunday 03:13 UTC).
- **Concept landing page section** "Learning journeys covering this" inserted between Tutorials and Prerequisites.
- **Tutorial-OP sidebar `otherResources` section** populated by JS-enrichment after `neighborhood` returns; ranked by concept-overlap count; capped at 5.
- **Five chassis-level deliverables** (§6.2.1 of arch spec): MCP client (4.1 implements 1 of 7 methods, scaffolds the rest), TTL helper, GC cron, neighborhood extension, CDS file.
- **Two new telemetry events:** `kg.learning_journey.linked_from_concept_page`, `kg.learning_journey.linked_from_sidebar`.
- **Test triad** (unit + hybrid + smoke) with hybrid fixtures: real captures for MCP + LLM, synthetic for HTML.

### Out of scope

- `journeyIncludesTutorial` predicate (Q2 deferred to 4.6 or later — would need LLM URL-to-slug mapping or deterministic URL-pattern extraction).
- Richer schema columns: `moduleCount`, `learningTrack` (Q3 — YAGNI; canonical journey page on `learning.sap.com` is the source of truth for those).
- Internal `/learning-journeys/<slug>/` Hugo pages — journeys link out to `learning.sap.com`.
- Admin CRUD UI for the `LearningJourneys` entity (rows are cron-managed; pruned by GC cron).
- `pinUntil` admin UI (chassis column exists but no per-row user-facing surface in 4.1; defer to 4.2 where blogs/videos actually need it).
- Further refactoring of Phase 1's tutorial extraction beyond the arch-spec-locked `extractConceptsCore` extraction.

## 1. Sub-phase decisions (Q1-Q8)

| # | Decision |
|---|---|
| Q1 | Body-fetch + cache, fall back to metadata on scrape failure (no MCP detail method for journeys). Body-fetcher is 4.1-specific (`srv/lib/learning-journey-body-fetcher.js`); not abstracted into shared client. |
| Q2 | Two predicates: `covers` (0.6 floor) + `journeyPrerequisite` (0.7 floor). `journeyIncludesTutorial` deferred. |
| Q3 | Minimal schema: chassis columns + `level` + `durationHours`. No `moduleCount`/`learningTrack`. |
| Q4 | Weekly cron `13 3 * * 0` (Sunday 03:13 UTC). Lock name `fetch-learning-journeys`. |
| Q5 | Concept page section position #2 (after Tutorials, before Prerequisites). Heading: "Learning journeys covering this". External-link rows: `<a target="_blank" rel="noopener">title</a> · {level} · {duration}h`. |
| Q6 | Sidebar `otherResources` ranked by concept-overlap count. JS-side enrichment after `neighborhood` returns; no new SPARQL named query. |
| Q7 | Body-fetcher tiered fallback: structured → readability → metadata. Per-tier counts logged for operational signal. |
| Q8 | Fixtures hybrid: real for MCP + LLM (one-time capture, frozen); synthetic for HTML (3 tier fixtures). |

## 2. Architecture

### 2.1 Data flow

```
┌─────────────────────────────────┐
│  Weekly cron @ Sunday 03:13 UTC │
│  fetch-learning-journeys-job.js │
└───────────────┬─────────────────┘
                │
                ▼
   ┌─────────────────────────┐       ┌──────────────────────────┐
   │  sapDevsClient.         │──────▶│  sap-devs MCP server     │
   │  searchLearningJourneys │       │  (24h cache, retry/      │
   │                         │◀──────│   schema-validated)      │
   └───────────┬─────────────┘       └──────────────────────────┘
               │ Array<{slug,title,level,duration,url}>
               ▼
   ┌─────────────────────────┐
   │  Upsert LearningJourneys│ — touches lastSeenAt; contentHash diff
   └───────────┬─────────────┘
               │ for each journey w/ contentHash change
               ▼
   ┌─────────────────────────┐       ┌──────────────────────────┐
   │  fetchJourneyBody(url)  │──────▶│  learning.sap.com        │
   │  (tier 1→2→3 fallback)  │       │  (HTTP GET, 3x retry)    │
   │                         │◀──────│                          │
   └───────────┬─────────────┘       └──────────────────────────┘
               │ {body: string, source: 'structured'|'readability'|'metadata'}
               ▼
   ┌─────────────────────────────────────────────────────────┐
   │  Embed journey body (cached on contentHash)             │
   │  Pre-fetch K=25 nearest concepts (registry hint)        │
   │  Pre-fetch K=10 nearest journeys (prereq candidates)    │
   │  Call extractConceptsFromLearningJourney({...})         │
   │  ↳ extractConceptsCore (LLM forced-tool-call, schema)   │
   └───────────────────────────┬─────────────────────────────┘
                               │ {covers: [...], journeyPrerequisites: [...]}
                               ▼
   ┌──────────────────────────────────────────────────────────┐
   │  Post-LLM validation (confidence floors, length caps,    │
   │    slug-existence check, self-reference guard)           │
   │  Persist:                                                │
   │  - LearningJourneyConceptLinks (predicate='covers')      │
   │  - LearningJourneyPrerequisites                          │
   │  - Merge-on-write new Concepts (cosine > 0.85)           │
   └──────────────────────────────────────────────────────────┘
```

### 2.2 Schema

`db/external-content.cds` (new file housing all Phase 4 per-type entities):

```cds
namespace com.sap.developers.ims.external;

using { managed, cuid } from '@sap/cds/common';
using { com.sap.developers.ims as ims } from '../db/knowledge-graph';

entity LearningJourneys : cuid, managed {
  // Chassis columns (per arch §2.1; every per-type entity has these):
  slug          : String(80) @assert.unique;
  title         : String(255);
  description   : String(1000);    // body-fetched 1-paragraph; null if scrape failed
  url           : String(500);
  sourceId      : String(120);     // SAP-side slug
  contentHash   : String(64);      // SHA-256 of (title + level + duration + body)
  firstSeenAt   : Timestamp @cds.on.insert: $now;
  lastSeenAt    : Timestamp;
  pinUntil      : Timestamp;       // chassis-uniformity; no UI in 4.1

  // Content-specific:
  level         : String(20);      // 'beginner' | 'intermediate' | 'advanced'
  durationHours : Decimal(5, 2);
}

entity LearningJourneyConceptLinks : cuid, managed {
  journey       : Association to LearningJourneys @assert.notNull;
  concept       : Association to ims.Concepts @assert.notNull;
  predicate     : String(20) default 'covers';
  confidence    : Decimal(3, 2);   // 0.60+ floor
  extractedAt   : Timestamp;
  modelVersion  : String(40);
}

entity LearningJourneyPrerequisites : cuid, managed {
  journey       : Association to LearningJourneys @assert.notNull;
  prerequisite  : Association to LearningJourneys @assert.notNull;
  reason        : String(500);     // 1-sentence LLM rationale
  confidence    : Decimal(3, 2);   // 0.70+ floor
  extractedAt   : Timestamp;
  modelVersion  : String(40);
}

annotate LearningJourneyConceptLinks with
  @assert.unique.journeyConcept : [journey, concept];

annotate LearningJourneyPrerequisites with
  @assert.unique.journeyPrereq : [journey, prerequisite];
```

The two link entities (`...ConceptLinks` and `...Prerequisites`) are separate because `journeyPrerequisite` doesn't fit the `(journey, concept, predicate)` shape — it's `journey → journey`.

### 2.3 Service exposure

The new entities are **NOT** exposed via OData in 4.1. Readers:

- Cron job (write path)
- Projection layer (`buildLearningJourneyTriples`, read path)
- `neighborhood` handler (read path for `otherResources`)
- `/build/concepts` handler (read path for the concept-page section)

If admin curation becomes necessary later (e.g. for `pinUntil` overrides), a future spec adds the projection to `KnowledgeGraphService`.

## 3. Extraction prompt strategy

### 3.1 System prompt

```
You are extracting concepts from an SAP Learning Journey description.

A Learning Journey is a structured curriculum on learning.sap.com that
teaches a coherent skill set across multiple modules (typically 3-20 hours
of content).

Your job is to identify:

1. **covers** — Concepts the journey discusses or teaches across its
   modules. Aim for 4-8 concepts (journeys are broader than tutorials).
   Each concept comes with a confidence in 0.0-1.0; floor 0.6.

2. **journeyPrerequisites** — OTHER learning journeys this journey
   assumes the learner has already taken. Only emit a prerequisite when
   the journey body or title explicitly references prior learning, OR
   when the level + topic structure makes the dependency obvious.
   Confidence floor 0.7 (false positives are costly — admin can't easily
   spot a wrong prereq).

You will be given:
- A K=25 list of concepts already in the registry. STRONGLY PREFER to
  reuse a registry slug when it fits the journey's content. Only mint a
  new slug when the journey discusses something genuinely outside any
  registry concept's scope.
- A K=10 list of OTHER learning journeys in the registry, by title.
  Reference these by slug when listing prerequisites.

For `covers`, output an array of objects each with:
- `slug` — kebab-case concept identifier (reuse from registry hint
  preferentially)
- `confidence` — float 0.0-1.0

For `journeyPrerequisites`, output an array of objects each with:
- `slug` — kebab-case slug of an OTHER learning journey from the
  prerequisite-candidates list
- `reason` — one sentence explaining why (surfaces in admin review)
- `confidence` — float 0.0-1.0

If the journey body is empty (metadata-only fallback), extract from
title + level + duration alone; emit fewer concepts (2-4) with lower
confidence (0.5-0.7 typical).
```

### 3.2 User prompt template

```
LEARNING JOURNEY:

Title: {{title}}
Level: {{level}}
Duration: {{durationHours}} hours
URL: {{url}}

Body ({{bodySource}}):
{{body | truncate 8000}}

REGISTRY HINT (25 nearest concepts by embedding similarity):
- {{registryHint[0].slug}}: {{registryHint[0].name}}. {{registryHint[0].description | truncate 100}}
- ... (24 more)

PREREQUISITE CANDIDATES (10 nearest learning journeys):
- {{prereqCandidates[0].slug}}: {{prereqCandidates[0].title}} ({{prereqCandidates[0].level}})
- ... (9 more)
```

Notes:
- `{{bodySource}}` is `structured`, `readability`, or `metadata`. System prompt's final paragraph adjusts confidence guidance when source is `metadata`.
- Body truncated to 8000 chars (~2000 tokens). Typical journey body after readability extraction is <4000 chars.
- Registry hint and prereq candidates are pre-fetched by the cron job per arch §4.

### 3.3 Forced-tool-call schema

```javascript
export const LEARNING_JOURNEY_EXTRACT_SCHEMA = {
  type: 'object',
  properties: {
    covers: {
      type: 'array',
      description: 'Concepts the journey covers. Aim for 4-8.',
      items: {
        type: 'object',
        required: ['slug', 'confidence'],
        properties: {
          slug: {
            type: 'string',
            pattern: '^[a-z0-9][a-z0-9-]{0,78}[a-z0-9]$',
          },
          confidence: { type: 'number', minimum: 0, maximum: 1 },
        },
      },
    },
    journeyPrerequisites: {
      type: 'array',
      description: 'Other journeys this one assumes as prior learning.',
      items: {
        type: 'object',
        required: ['slug', 'reason', 'confidence'],
        properties: {
          slug: { type: 'string', pattern: '^[a-z0-9][a-z0-9-]{0,78}[a-z0-9]$' },
          reason: { type: 'string', maxLength: 500 },
          confidence: { type: 'number', minimum: 0, maximum: 1 },
        },
      },
    },
  },
  required: ['covers', 'journeyPrerequisites'],
};
```

### 3.4 Post-LLM validation (in the adapter)

After the schema-validated response returns:

1. **Confidence floors:** drop `covers` entries with `confidence < 0.6`; drop `journeyPrerequisites` with `confidence < 0.7`.
2. **Length caps:** truncate `covers` to top 8 by confidence (desc); `journeyPrerequisites` to top 5.
3. **Slug existence for prereqs:** `journeyPrerequisites[].slug` MUST reference a row already in `LearningJourneys`. Non-existent slugs dropped (LLM occasionally hallucinates plausible journey slugs).
4. **Self-reference guard:** `journeyPrerequisites[].slug === currentJourney.slug` dropped.

### 3.5 Per-tier K adjustments

Per arch §4.3, K is passed in by the cron job:

| Tier | K_concepts | K_prereqs | Body cap | Confidence guidance |
|---|---|---|---|---|
| `structured` | 25 | 10 | 8000 chars | Standard (0.6-0.9 typical) |
| `readability` | 25 | 10 | 8000 chars | Standard |
| `metadata` | 15 | 10 | (empty) | Reduced (0.5-0.7 typical); emit 2-4 covers instead of 4-8 |

### 3.6 Cost ceiling

New runtime config setting **lives in `ChatSettings`** (same place Phase 3 added similar flags): `learningJourneyExtractBudgetPerDay : Integer` (default 500). Cron checks budget before each run; logs `budget exhausted, skipping cycle` and exits cleanly if hit. One weekly cycle processes ~150 journeys; budget allows ~3 cycles per week of headroom or one full re-extract.

### 3.7 Failure modes

| Mode | Behavior |
|---|---|
| LLM call fails (network, rate limit) | Adapter throws; cron job catches per-journey; logs; skips this journey for this cycle; `lastSeenAt` not updated → next cycle retries. |
| Schema validation fails | Adapter throws (core enforces); same handling. |
| Empty `covers` array | Persist the journey row (so it exists for other journeys' prerequisites) but no concept links. Concept-page section shows zero rows for this journey. |
| Empty `journeyPrerequisites` | Persist normally. Most journeys won't have explicit prereqs. |

## 6. Acceptance criteria

Sub-phase 4.1 is "shipped" when all of these are true:

- [ ] `LearningJourneys`, `LearningJourneyConceptLinks`, `LearningJourneyPrerequisites` tables exist in DEV HANA.
- [ ] Weekly cron has run at least once and populated `LearningJourneys` with rows.
- [ ] Concept pages for at least 3 well-known concepts (e.g. `cap-handlers`, `hana-cloud`, `btp-architecture` — OR any 3 concepts with ≥1 covering journey after the first cron run, if these specific slugs aren't yet in the registry) show non-empty "Learning journeys covering this" sections.

- [ ] `kg.learning_journey.linked_from_concept_page` and `kg.learning_journey.linked_from_sidebar` events fire as expected.
