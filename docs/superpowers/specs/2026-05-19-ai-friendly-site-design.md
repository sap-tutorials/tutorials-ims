# AI-Friendly Site Design

**Date:** 2026-05-19
**Status:** Approved by Tom, pending spec review and implementation plan

## Summary

Add SEO and AI-assistant friendliness to the SAP Developers Tutorials platform (Hugo + CAP + AppRouter, replacing AEM as the frontend for developers.sap.com). Covers fifteen items the user requested in one bundled design: foundational `baseURL` and brand consistency, full per-page metadata (title, description, canonical, OG, Twitter Card, robots directives, keywords, authors), JSON-LD (`Organization`, `WebSite`, `HowTo`, `Course`, `BreadcrumbList`, `FAQPage`), site files (`robots.txt`, `sitemap.xml`, `AGENTS.md`, `llms.txt`, `llms-full.txt`), HTTP-level `Content-Signal` headers, web font `display: swap`, and a server-rendered semantic homepage that replaces the current empty `<div id="tutorial-navigator">` shell.

## Goals

1. Make every public page crawlable, citable, and machine-readable by AI assistants and search engines.
2. Establish one canonical brand string ("SAP Developers Tutorials") and one canonical URL (`https://developers.sap.com`) used consistently across `<title>`, OG, Twitter, JSON-LD, robots, sitemap, llms.txt, and AGENTS.md.
3. Signal an "allow citation, discourage training" policy in machine-readable form (HTTP header + meta tag + AGENTS.md + llms.txt preamble).
4. Ship as a single bundled change to the Hugo build pipeline plus a one-line approuter response-header config — no CAP changes, no migration, no breaking API changes.

## Non-Goals

- Translating tutorial content into other languages (`og:locale` is hardcoded `en_US`).
- Designing a per-tutorial bespoke OG image (we ship one default branded image).
- Authoring per-tutorial FAQ content by hand (FAQs are auto-generated from existing frontmatter).
- Replacing the JS tutorial navigator. It stays as a progressive enhancement on top of server-rendered HTML.
- Submitting the new sitemap/robots.txt to Google Search Console / Bing Webmaster (operational follow-up, not part of this change).
- Shipping any analytics or telemetry to measure AI citation rate.

## Decisions Made During Brainstorming

| Decision | Choice |
|---|---|
| Scope | All 15 items as one bundled PR |
| Homepage rendering | SSR hybrid — Hugo renders content, JS navigator enhances |
| Canonical hostname | `https://developers.sap.com` (cutover target) |
| Brand string | `SAP Developers Tutorials` |
| AI bot policy | Allow citation, signal `ai-train=no` via `Content-Signal` |
| Tutorial JSON-LD type | `HowTo` for tutorials, `Course` for missions |
| FAQ source | Auto-generate from frontmatter (`youWillLearn`, `prerequisites`, `time`, `level`) |
| AGENTS.md scope | Both — public `/AGENTS.md` for visitor agents AND repo-root `AGENTS.md` for codebase agents |
| Twitter handle | `@sapdevs` |
| OG default image | SAP logo on branded background |

## Architecture

Hugo is the source of truth for all SEO/AI metadata. Tutorial HTML is served from HANA but was *built* by Hugo — meta tags ride along inside the gzip-compressed BLOB and survive the publish → HANA → decompress → serve round trip. AppRouter routes `/tutorials/*` to the CAP `/content/tutorials/:slug` endpoint, which decompresses and serves the HTML verbatim. No CAP code changes are needed.

The single AppRouter change is response-header configuration in [approuter/xs-app.json](approuter/xs-app.json) to add `Content-Signal` and `X-Robots-Tag` headers to HTML routes.

`robots.txt`, `sitemap.xml`, `llms.txt`, and `llms-full.txt` are all generated by Hugo as output formats, written to `hugo/public/`, and served as static files by AppRouter.

This single change unblocks every other deliverable: `.Permalink` becomes absolute, sitemap URLs become valid, OG `url` works correctly, canonical links resolve.

### Head Partials (T1–T11)

Replace the current single [hugo/layouts/partials/head.html](hugo/layouts/partials/head.html) with five partials:

```
hugo/layouts/partials/
  head.html              # orchestrator: meta charset/viewport, theme script, fonts, includes the four below
  head-meta.html         # T1–T6: title, description, canonical, robots, keywords, authors, content-signal meta
  head-og.html           # T7, T8: Open Graph + Twitter Card
  head-jsonld.html       # T10: per-page JSON-LD (HowTo, Course, BreadcrumbList, FAQPage)
  site-jsonld.html       # T9: sitewide Organization + WebSite (rendered once in baseof.html)
```

Each partial stays under ~80 lines so the JSON-LD branching logic stays readable.

#### T1–T6: head-meta.html

```html
{{- $brand := .Site.Params.brand -}}
{{- $title := cond .IsHome $brand (printf "%s | %s" .Title $brand) -}}
{{- $desc := .Params.description | default .Site.Params.defaultDescription -}}

<title>{{ $title }}</title>
<meta name="description" content="{{ $desc | plainify | truncate 160 }}">
<link rel="canonical" href="{{ .Permalink }}">
<meta name="robots" content="index, follow, max-image-preview:large, max-snippet:-1, max-video-preview:-1">
<meta name="content-signal" content="index=yes, ai-train=no, ai-search=yes">

{{- with .Params.tags }}
<meta name="keywords" content="{{ delimit . ", " }}">
{{- end }}

{{- with .Params.author }}
<meta name="author" content="{{ . }}">
{{- end }}

{{- range .Aliases }}
<link rel="alternate" href="{{ . | absURL }}">
{{- end }}
```

Title behavior: home page becomes `SAP Developers Tutorials` (no duplication); every other page becomes `<page title> | SAP Developers Tutorials`. Fixes the current `"SAP Tutorial Platform | SAP Tutorial Platform"` bug.

Robots directives include `max-image-preview:large` (item #15), plus `max-snippet:-1` and `max-video-preview:-1` so search engines can show full-length previews. Aliases (the legacy `.html` URLs from the old AEM era) get `<link rel="alternate">` so they don't compete with the canonical.

#### T10: head-jsonld.html (per-page)

Branches on `.Type`:

**Tutorials → `HowTo` + `BreadcrumbList` + `FAQPage` (when frontmatter has both `youWillLearn` and `prerequisites`):**

```jsonc
{
  "@context": "https://schema.org",
  "@type": "HowTo",
  "name": "{{ .Title }}",
  "description": "{{ .Params.description }}",
  "totalTime": "PT{{ .Params.time }}M",
  "datePublished": "{{ .Date.Format "2006-01-02" }}",
  "dateModified": "{{ .Lastmod.Format "2006-01-02" }}",
  "educationalLevel": "{{ .Params.level }}",
  "author": { "@type": "Person", "name": "{{ .Params.author }}" },
  "publisher": { "@id": "https://developers.sap.com/#organization" },
  "step": [
    {{ range $i, $step := .Params.steps }}
    { "@type": "HowToStep", "position": {{ add $i 1 }}, "name": "{{ $step.title }}" }{{ if not (eq $i (sub (len $.Params.steps) 1)) }},{{ end }}
    {{ end }}
  ]
}
```

FAQPage auto-generation (canonical four Q→A pairs):

| Question | Answer source |
|---|---|
| "What will I learn?" | `.Params.youWillLearn` joined |
| "What do I need before I start?" | `.Params.prerequisites` joined |
| "How long does this take?" | `"{{ .Params.time }} minutes"` |
| "What level is this?" | `.Params.level` |

**Missions → `Course` + `BreadcrumbList`:**

```jsonc
{
  "@context": "https://schema.org",
  "@type": "Course",
  "name": "{{ .Title }}",
  "description": "{{ .Params.description }}",
  "provider": { "@id": "https://developers.sap.com/#organization" },
```

**Groups → `Course`** (groups are completion paths within missions, semantically the same shape).

**Home / tags / generic pages → `BreadcrumbList` only.**

**Progressive enhancement contract:** the JS `navigator.js` mounts into `#tutorial-navigator` exactly as today. The new sections sit *above* and don't depend on JS. If JS fails or a crawler doesn't execute it, users still see featured missions, recent tutorials, and the topic index.

**One verification step before relying on `.ByLastmod`:** Hugo derives `.Lastmod` from frontmatter `lastmod`/`date` or git mtime. Most tutorials have `lastmod` populated by `fetch-tutorials.ts` from the GitHub commit timestamp. Implementation must verify this before relying on it for sitemap and homepage ordering; if any tutorials lack it, fix `fetch-tutorials.ts` to set `lastmod` from the GitHub commit timestamp.

**Tutorials list page** at [hugo/layouts/tutorials/list.html](hugo/layouts/tutorials/list.html) — ensure it renders a paginated, crawlable list of all tutorials. The home noscript fallback links to `/tutorials/` so this list page must work.

#### S1b: Content-Signal HTTP header

Add to [approuter/xs-app.json](approuter/xs-app.json) for HTML routes (`/`, `/tutorials/*`, `/missions/*`, `/groups/*`, `/tags/*`):

```json
{
  "responseHeaders": [
    { "name": "Content-Signal", "value": "index=yes, ai-train=no, ai-search=yes" },
    { "name": "X-Robots-Tag", "value": "index, follow, max-image-preview:large" }
  ]
}
```

The header gets paired with the `<meta name="content-signal">` already in head-meta.html, so clients reading either form see the same signal.

#### S2: hugo/layouts/_default/sitemap.xml

```xml
{{- printf "<?xml version=\"1.0\" encoding=\"utf-8\" standalone=\"yes\"?>" | safeHTML }}
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
{{- range .Data.Pages }}
{{- if and (not .Params.private) (ne .Kind "taxonomy") }}
  <url>
    <loc>{{ .Permalink }}</loc>

    {{- if .IsHome }}<changefreq>daily</changefreq><priority>1.0</priority>
    {{- else if eq .Type "tutorials" }}<changefreq>weekly</changefreq><priority>0.8</priority>
    {{- else if or (eq .Type "missions") (eq .Type "groups") }}<changefreq>weekly</changefreq><priority>0.7</priority>
    {{- else }}<changefreq>monthly</changefreq><priority>0.5</priority>{{ end }}
  </url>
{{- end }}
{{- end }}
</urlset>
```

Excludes `taxonomy` pages (auto-generated tag lists with no real `lastmod`) to avoid bloating the sitemap with low-value URLs.

```markdown
# AGENTS.md

This is the AGENTS.md for the SAP Developers Tutorials platform codebase. AI coding agents (Claude Code, Cursor, Copilot, Aider) working in this repo should read this file and CLAUDE.md.

## Stack
- Hugo static site (hugo/) for tutorial pages, missions, groups
- CAP Node.js backend (srv/) on SAP HANA Cloud
- Vue 3 public-facing apps (apps/, display-app/)
- SAPUI5/Fiori Elements admin shell (app/admin-shell/)

## Authoritative guidance
**Read [CLAUDE.md](./CLAUDE.md) for the full project guide** — commands, architecture, gotchas, testing strategy. AGENTS.md is a pointer; CLAUDE.md is the canonical source.

## Quick conventions
- Hugo content under `hugo/content/tutorials/` is generated — never hand-edit. Modify parsers in `scripts/parsers/` or upstream tutorials in the `sap-tutorials` GitHub org.
- Tutorial HTML is served from HANA BLOBs, not static files. After Hugo build, run `npm run publish-content`.
- Run `npm test` (unit, in-memory SQLite) before committing. `npm run test:hybrid` requires `cf login`.
- Use `cds-mcp` to look up CDS definitions and CAP API docs before editing CDS or CAP code.

## Out of scope for codebase agents
- Don't modify `hugo/content/tutorials/*.md` directly.
- Don't touch `gen/` (CAP build output) — regenerate via `cds build`.
- Don't bypass `@requires`/`@restrict` annotations on services.
```

## Data Flow

```
Author edits tutorial markdown in sap-tutorials GitHub org
  └─ npm run fetch-tutorials  ──>  hugo/content/tutorials/*.md (with rich frontmatter)
       └─ npm run build:hugo  ──>  hugo/public/
                                    ├── index.html               (SSR home, full meta + JSON-LD)
                                    ├── tutorials/<slug>/index.html  (HowTo + FAQPage + meta)
```

## Error Handling

This change is metadata-only and additive. Failure modes are:

- **A tutorial frontmatter field is missing** (e.g. no `author`, no `description`). Templates use `with` and `default` to skip missing fields gracefully. A tutorial with no `description` falls back to `Site.Params.defaultDescription`. A tutorial with no `author` skips the `<meta name="author">` and `article:author` tags.
- **`.Lastmod` is missing for some pages.** Sitemap omits `<lastmod>` for that URL (`with .Lastmod` guards it). Homepage `.ByLastmod.Reverse` orders by zero-value dates last. If this turns out to be a widespread problem, fix it in `fetch-tutorials.ts` by writing `lastmod` from the GitHub commit timestamp.
- **`hugo/static/img/og-default.png` missing at build.** Hugo doesn't error; the OG `image` tag points to a 404 URL. Pre-flight: confirm the file exists before merge. The image is the SAP logo on a branded background, designed once.
- **Hugo output format misconfiguration.** If `[outputs] home` doesn't include the new formats, the files don't generate. Smoke test verifies `/llms.txt`, `/llms-full.txt`, `/robots.txt`, `/sitemap.xml`, `/AGENTS.md` all return 200.

## Dependencies and Risks

- **Hugo `.Lastmod` reliability.** Implementation must spot-check that fetched tutorials have `lastmod` populated. If not, fix `fetch-tutorials.ts` to write `lastmod` from GitHub commit timestamp before relying on it for sitemap and homepage.
- **OG default image asset.** Must be designed and added to `hugo/static/img/og-default.png` (1200×630, SAP logo on branded background) before merge. One-time content task.
- **Approuter response headers.** `xs-app.json` syntax for `responseHeaders` must be tested in dev before deploy — incorrect config could break HTML routes. Smoke test validates both header presence and that HTML still serves.
- **Content-Signal is a draft standard.** No risk of breaking anything; just possible some clients don't read it yet. The `<meta>` tag fallback covers most cases.
- **`@id` reference resolution in JSON-LD.** Per-page `HowTo`/`Course` blocks reference `https://developers.sap.com/#organization` (defined in sitewide block). This works in JSON-LD `@graph` semantics, but smoke test should parse and assert the reference resolves.
